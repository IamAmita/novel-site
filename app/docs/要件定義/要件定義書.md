# 小説投稿サイト 要件定義書

## 1. 概要

### 1.1 ドキュメント情報
- **作成日**: 2025年1月
- **作成者**: 開発者
- **バージョン**: 1.0
- **対象システム**: 設定管理・共同著作対応小説投稿サイト

### 1.2 プロジェクトの目的
- 設定管理機能の充実した小説投稿サイトの構築
- 共同作成・依頼機能による創作コミュニティの形成
- 使いやすさ重視の小規模サイト運営
- **品質重視**: 納期よりも満足度（品質）を重視

### 1.3 開発方針
- **個人開発**: 1名での開発・運用
- **品質重視**: 納期制限なし、満足度を最優先
- **段階的開発**: フェーズ分けによる段階的実装
- **継続改善**: 運用開始後も継続的な機能改善

## 2. 機能要件

### 2.1 機能要件の概要
詳細な機能要件については、別途「機能要件定義書.md」を参照してください。

#### 2.1.1 主要機能カテゴリ
1. ユーザー管理機能
2. 小説投稿・管理機能
3. 設定管理機能
4. 共同著作機能
5. 権限管理機能
6. コミュニケーション機能
7. 掲示板機能
8. 閲覧・検索機能
9. 管理機能

#### 2.1.2 実装フェーズ
- **フェーズ1**: 基本機能（ユーザー管理、小説投稿、設定管理、権限管理）

## 3. 非機能要件

### 3.1 パフォーマンス要件
- **ページロード時間**: 3秒以内（品質重視のため余裕を持った設定）
- **同時接続数**: 100ユーザー（初期）、将来的に1000ユーザー対応
- **データベース応答時間**: 1秒以内
- **画像アップロード**: 10MB以内、5秒以内
- **検索応答時間**: 2秒以内
- **優先度**: 品質重視のため、パフォーマンスは十分な余裕を持って設計

### 3.2 可用性要件
- **システム稼働率**: 99%以上（個人運用でも安定性重視）
- **メンテナンス時間**: 月1回、2時間以内
- **バックアップ**: 日次自動バックアップ
- **障害復旧時間**: 4時間以内
- **データ保護**: 重要なデータは複数箇所にバックアップ

### 3.3 セキュリティ要件
- **データ暗号化**: 個人情報の暗号化保存
- **通信暗号化**: HTTPS必須
- **セッション管理**: セッションハイジャック対策
- **SQLインジェクション対策**: 必須
- **XSS対策**: 必須
- **CSRF対策**: 必須
- **2段階認証**: オプション機能として実装
- **ログイン履歴**: セキュリティ監査用の詳細ログ

### 3.4 拡張性要件
- **ユーザー数拡張**: 将来的に1000ユーザー対応
- **データ量拡張**: 将来的に10GB対応
- **機能追加**: モジュール化設計で拡張しやすく
- **API拡張**: RESTful API設計で将来的な拡張に対応

### 3.5 ユーザビリティ要件
- **レスポンシブデザイン**: PC、タブレット、スマートフォン対応
- **アクセシビリティ**: 基本的なアクセシビリティ対応
- **直感的なUI**: 使いやすさを重視した設計
- **エラーハンドリング**: 分かりやすいエラーメッセージ
- **ヘルプ機能**: 必要に応じてヘルプ・チュートリアル機能

## 4. 運用要件

### 4.1 運用体制
- **管理者**: 1名（個人開発）
- **監視体制**: 自動監視 + 手動チェック
- **対応時間**: 平日9-18時（緊急時は24時間対応）
- **連絡手段**: メール、チャットツール

### 4.2 監視・ログ要件
- **アクセスログ**: 全ページアクセスの記録
- **エラーログ**: システムエラーの詳細記録
- **セキュリティログ**: 不正アクセス・異常操作の記録
- **パフォーマンスログ**: 応答時間・リソース使用量の記録
- **監視アラート**: 障害・異常時の自動通知

### 4.3 バックアップ・復旧要件
- **バックアップ対象**: データベース、ファイル、設定ファイル
- **バックアップ頻度**: 日次（差分）、週次（完全）
- **保持期間**: 1ヶ月（日次）、3ヶ月（週次）
- **復旧テスト**: 月1回の復旧テスト実施
- **オフサイト保存**: クラウドストレージへの自動保存

### 4.4 保守計画
- **定期メンテナンス**: 月1回、2時間以内
- **セキュリティアップデート**: 月1回
- **機能アップデート**: 四半期1回（品質重視のため十分なテスト期間）
- **データベース最適化**: 月1回

### 4.5 障害対応
- **障害レベル定義**: 軽微・重要・緊急
- **対応時間**: 軽微4時間、重要2時間、緊急30分
- **復旧手順**: 障害別の復旧手順書
- **報告体制**: ユーザーへの影響報告

## 6. 技術要件

### 6.1 技術選定基準
- **機能性・拡張性重視**: 学習コストや開発速度よりも機能性・拡張性を優先
- **品質重視**: 成熟した技術、豊富なライブラリ、セキュリティ対策
- **学習しやすさ**: 日本語ドキュメント、活発なコミュニティ
- **将来性**: 継続的な開発、長期的なサポート
- **運用自動化**: CI/CD、コンテナ化、クラウド対応

### 6.2 技術選定結果

#### 6.2.1 フロントエンド技術
- **フレームワーク**: Vue.js 3 + TypeScript
- **UIフレームワーク**: Vuetify 3
- **状態管理**: Pinia
- **ルーティング**: Vue Router 4
- **HTTP通信**: Axios
- **ビルドツール**: Vite
- **選定理由**:
  - 学習コストが低く、段階的学習が可能
  - 直感的な文法、豊富な開発者ツール
  - TypeScript対応で型安全性を確保
  - 活発なコミュニティ、継続的な開発

#### 6.2.2 バックエンド技術
- **言語**: Python 3.11
- **フレームワーク**: Django 4
- **REST API**: Django REST Framework
- **認証**: Django REST Framework JWT
- **管理画面**: Django Admin
- **タスクキュー**: Celery + Redis
- **キャッシュ**: Redis
- **選定理由**:
  - "バッテリー付き"で高機能、豊富なライブラリ
  - 日本語ドキュメント充実、学習しやすい
  - セキュリティ対策が充実、成熟したフレームワーク
  - 将来の機能追加に対応可能

#### 6.2.3 データベース技術
- **データベース**: PostgreSQL 15
- **全文検索**: PostgreSQL Full-Text Search
- **JSON型**: JSONB
- **バックアップ**: AWS RDS自動バックアップ
- **選定理由**:
  - 高機能（JSON型、全文検索、地理情報等）
  - データ整合性、ACID準拠
  - 豊富な拡張機能、カスタム型定義
  - オープンソース、継続的な開発

#### 6.2.4 インフラ・運用技術
- **コンテナ化**: Docker + Docker Compose
- **クラウド**: AWS（ECS, RDS, S3, CloudFront, CloudWatch）
- **CI/CD**: GitHub Actions
- **バージョン管理**: Git + GitHub
- **選定理由**:
  - AWS環境での開発経験を活かせる
  - 自動スケーリング、ロードバランサー、監視機能
  - Dockerによる環境統一、GitHub Actionsで自動デプロイ
  - 使用量に応じた課金、コスト効率

### 6.3 開発環境要件
- **OS**: Windows
- **IDE**: Cursor (VSCodeベース)
- **コンテナ**: Docker Desktop
- **バージョン管理**: Git
- **開発サーバー**: Docker Compose
- **テスト環境**: Docker環境内でのテスト実行

### 6.4 本番環境要件
- **サーバー環境**: AWS ECS (Fargate)
- **ドメイン**: 独自ドメイン取得
- **SSL証明書**: AWS Certificate Manager
- **CDN**: AWS CloudFront
- **監視ツール**: AWS CloudWatch
- **ログ管理**: CloudWatch Logs

### 6.5 セキュリティ要件
- **認証・認可**: JWT、セッション管理
- **データ保護**: 暗号化、アクセス制御
- **通信保護**: HTTPS、WAF
- **脆弱性対策**: 定期的なセキュリティチェック
- **コンテナセキュリティ**: イメージスキャン、最小権限原則

### 6.6 開発・実装計画

#### 6.6.1 実装しながら学習の進め方
- **Step 1: 開発環境構築（1週間）**
  - Docker環境の構築
  - Gitリポジトリの初期化
  - 基本的なHello World実装

- **Step 2: 基本機能実装（2-3ヶ月）**
  - ユーザー登録・認証（Django + Vue.js）
  - 小説投稿機能（CRUD操作）
  - 設定管理機能（階層構造）

- **Step 3: 高度な機能実装（3-4ヶ月）**
  - 権限管理機能
  - 検索・フィルタ機能
  - ファイルアップロード

- **Step 4: 運用・改善（継続）**
  - AWSデプロイ
  - 監視・ログ設定
  - パフォーマンス改善

#### 6.6.2 学習重点項目
- **Python**: 基礎文法 → Djangoフレームワーク
- **Vue.js**: 基礎 → TypeScript → 高度な機能
- **PostgreSQL**: 基礎 → Django ORM → 高度なクエリ
- **Docker**: 基礎 → マルチコンテナ → 本番環境
- **AWS**: ECS → RDS → S3 → CloudWatch

#### 6.6.3 品質確保のための取り組み
- **テスト駆動開発**: 単体テスト、結合テスト
- **コードレビュー**: 自己レビュー、ベストプラクティス適用
- **ドキュメント**: 実装時のドキュメント整備
- **継続的改善**: 定期的なリファクタリング
