# operation_histories テーブル詳細

---

## 概要
システム全体の運用履歴を管理するテーブルです。通報処理、テンプレート変更、対象種別変更、管理者操作など、重要な運用操作の履歴を一元管理し、監査・追跡・分析を可能にします。

---

## テーブル定義

| 属性名             | 型         | 必須 | 一意 | 説明                                 |
|--------------------|------------|------|------|--------------------------------------|
| id                 | int        | ○    | ○    | 履歴ID（主キー）                     |
| operation_type     | tinyint    | ○    |      | 操作種別                             |
| target_type        | tinyint    |      |      | 操作対象種別                         |
| target_id          | int        |      |      | 操作対象ID                           |
| operator_id        | int        | ○    |      | 操作者ID（外部キー）                 |
| description        | text       |      |      | 操作説明（自由記述）                 |
| before_data        | text       |      |      | 変更前データ（文字列形式）           |
| after_data         | text       |      |      | 変更後データ（文字列形式）           |
| created_at         | datetime   | ○    |      | 操作日時                             |
| updated_at         | datetime   |      |      | 更新日時                             |

---

## インデックス

| インデックス名 | 種類 | 説明 | カラム |
|----------------|------|------|--------|
| PRIMARY KEY | 主キー | 履歴IDの主キー | id |
| INDEX | 通常 | 操作種別検索用 | operation_type |
| INDEX | 通常 | 操作者検索用 | operator_id |
| INDEX | 通常 | 操作日時検索用 | created_at |
| INDEX | 複合 | 対象検索用 | target_type, target_id |
| INDEX | 複合 | 操作者・日時検索用 | operator_id, created_at |

---

## 制約条件

### 主キー制約
- `id`: 自動採番（AUTO_INCREMENT）

### 外部キー制約
- `operator_id` → `users.id`: 操作者ユーザーテーブルを参照
- `target_type` → `target_types.id`: 対象種別定義テーブルを参照

### チェック制約
- `operation_type`: 0～9のいずれかである必要があります

---

## 設計補足

### 操作種別（operation_type）
- `0`: 通報処理
- `1`: テンプレート変更
- `2`: 対象種別変更
- `3`: 管理者操作
- `4`: システム設定変更
- `5`: ユーザー管理操作
- `6`: コンテンツ管理操作
- `7`: 権限管理操作
- `8`: セキュリティ関連操作
- `9`: その他

### 操作対象種別（target_type）
- `0`: コメント
- `1`: 小説
- `2`: 設定
- `3`: 話（チャプター）
- `4`: レビュー
- `5`: ユーザー
- `6`: グループ
- `7`: テンプレート
- `8`: 対象種別定義
- `9`: システム設定

### 操作説明（description）
- 自由記述で操作の詳細を記録
- 例：「利用規約違反のため通報を承認し、警告メッセージを送信」
- 例：「通知テンプレートの文言を修正」
- 例：「対象種別「話」を新規追加」

### 変更前後データ（before_data, after_data）
- 文字列形式で変更前後のデータを記録
- 例：テンプレート変更の場合
```
テンプレートID: 5
テンプレート文: 変更前のテンプレート文
言語: 日本語
```

## データ例

| id | operation_type | target_type | target_id | operator_id | description | 説明 |
|----|----------------|-------------|-----------|-------------|-------------|------|
| 1 | 0 | 0 | 123 | 1 | 利用規約違反のため通報を承認し、警告メッセージを送信 | コメント通報を承認 |
| 2 | 1 | 7 | 5 | 1 | 通知テンプレートの文言を修正 | 通知テンプレートを変更 |
| 3 | 2 | 8 | 3 | 1 | 対象種別「話」を新規追加 | 対象種別「話」を追加 |
| 4 | 3 | 5 | 456 | 1 | アカウント停止のためユーザーを無効化 | ユーザーアカウントを停止 |
| 5 | 4 | 9 | 1 | 1 | サイトメンテナンス設定を変更 | サイト設定を変更 |

## 関連テーブル

- `users`: 多対1の関係（操作者）
- `target_types`: 多対1の関係（対象種別定義）
- `reports`: 1対多の関係（通報処理履歴）
- `templates`: 1対多の関係（テンプレート変更履歴）

---

## 運用上の注意点

1. **履歴の完全性**: 重要な操作は必ず履歴を記録
2. **データサイズ管理**: JSONデータのサイズ制限と圧縮
3. **パフォーマンス**: 大量履歴データの効率的な管理
4. **プライバシー保護**: 個人情報を含む履歴の適切な管理
5. **バックアップ**: 履歴データの定期的なバックアップ
6. **監査対応**: 監査要件に応じた履歴の保持期間管理
7. **検索機能**: 多様な条件での履歴検索機能の提供
8. **自動化**: 定期的な履歴データのクリーンアップ
