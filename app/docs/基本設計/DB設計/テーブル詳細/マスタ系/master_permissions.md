# master_permissionss テーブル詳細

---

## 概要
システム全体の権限定義を管理するマスタテーブルです。オーナー、管理者、編集者、閲覧者など、様々な権限の定義を一元管理し、システム全体で一貫した権限管理を可能にします。

---

## テーブル定義

| 属性名         | 型         | 必須 | 一意 | 説明                                 |
|----------------|------------|------|------|--------------------------------------|
| id             | int        | ○    | ○    | 権限定義ID（主キー）                 |
| name           | varchar    | ○    | ○    | 権限名（例：オーナー、管理者、編集者等）|
| description    | text       |      |      | 権限の説明                           |
| created_at     | datetime   | ○    |      | 登録日時                             |
| updated_at     | datetime   |      |      | 更新日時                             |

---

## インデックス

| インデックス名 | 種類 | 説明 | カラム |
|----------------|------|------|--------|
| PRIMARY KEY | 主キー | 権限定義IDの主キー | id |
| UNIQUE | 一意 | 権限名の一意制約 | name |
| INDEX | 通常 | 登録日時検索用 | created_at |

---

## 制約条件

### 主キー制約
- `id`: 自動採番（AUTO_INCREMENT）

### 一意制約
- `name`: 権限名は一意である必要があります

### チェック制約
- `name`: 空文字列は許可しない

---

## 設計補足

### 権限名（name）
- システム全体で一意である必要があります
- 例：「owner」（オーナー）、「admin」（管理者）、「editor」（編集者）、「viewer」（閲覧者）など
- プログラム内の定数として使用

### 権限の説明（description）
- 権限の詳細な説明
- 何ができるか、何ができないかを明記

---

## 関連テーブル

- `user_permissions`: 1対多の関係（ユーザー権限管理）

---

## 運用上の注意点

1. **権限名**: システム全体で一意である必要があります
2. **権限階層**: 権限の優先順位の管理
3. **監査**: 権限変更の履歴管理
4. **一貫性**: システム全体で統一された権限管理
5. **拡張性**: 新しい権限の追加を考慮した設計
