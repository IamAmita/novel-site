# 小説情報テーブル（novel_info）

---

## 概要
小説のタイトルや説明など、作品の詳細情報を管理するテーブル。novelsテーブルと1対1の関係を持ち、情報の分離による拡張性・パフォーマンス向上を目的とする。

---

## テーブル定義

| 属性名        | 型            | 必須 | 一意 | 説明                           |
|---------------|---------------|------|------|--------------------------------|
| id            | int           | ○    | ○    | 小説情報ID（主キー）           |
| novel_id      | int           | ○    |      | 小説ID（novels.idを参照、NOT NULL, 一意） |
| title         | varchar(255)  | ○    |      | 小説タイトル                   |
| description   | text          |      |      | 小説の説明                     |
| delete_flg    | tinyint(1)    | ○    |      | 削除フラグ（0:有効, 1:削除済み） |
| created_at    | datetime      | ○    |      | 作成日時                       |
| updated_at    | datetime      | ○    |      | 更新日時                       |
| deleted_at    | datetime      |      |      | 削除日時                       |

---

## インデックス

| インデックス名           | 種類 | 説明               | カラム                |
|------------------------|------|-------------------|----------------------|
| PRIMARY KEY            | 主キー | 小説情報IDの主キー | id                   |
| UNIQUE                 | 一意  | 小説IDの一意       | novel_id             |
| INDEX                  | 通常 | タイトル検索用     | title                |
| INDEX                  | 通常 | 削除フラグ検索用   | delete_flg           |
| INDEX                  | 通常 | 作成日時検索用     | created_at           |
| INDEX                  | 通常 | 更新日時検索用     | updated_at           |
| INDEX                  | 通常 | 削除日時検索用     | deleted_at           |
| FULLTEXT               | 全文検索 | タイトルの全文検索用 | title |

---

## 制約条件

### 主キー制約
- `id`: 自動採番（AUTO_INCREMENT）

### 外部キー制約
- `novel_id` → `novels.id`（NOT NULL, 一意）

### チェック制約
- `title`: 空文字列でないこと
- `delete_flg` IN (0, 1)

---

## 設計補足

- **データ分離**: 小説の基本情報（novels）と詳細情報（novel_info）を分離し、拡張性・パフォーマンス向上を図る。
- **1対1の関係**: 各小説は必ず1つの情報レコードを持つ。
- **論理削除**: `delete_flg`で論理削除を実現し、`deleted_at`で削除日時を記録。
- **検索機能**: タイトルによる部分一致・全文検索に対応。

---

## 関連テーブル

- `novels`: 1対1の関係（小説の基本情報）

---

## 運用上の注意点

1. **データ整合性**: 小説作成時は必ず情報レコードも作成
2. **検索最適化**: 全文検索インデックスの定期的な最適化
3. **パフォーマンス**: 一覧表示時はJOINを避ける
4. **バックアップ**: 小説情報の定期的なバックアップ
5. **論理削除**: 削除された情報の適切な処理
6. **削除日時管理**: 削除日時の正確な記録
