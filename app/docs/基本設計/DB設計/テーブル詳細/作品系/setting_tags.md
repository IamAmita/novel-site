# 設定タグ関連テーブル（setting_tags）

---

## 概要
設定とタグの多対多関係を管理する中間テーブル。設定に複数のタグを付けることができ、タグによる検索や分類を可能にする。

---

## テーブル定義

| 属性名 | 型 | 必須 | 一意 | 説明 |
|--------|----|------|------|------|
| id | int | ○ | ○ | 関連ID（主キー） |
| setting_id | int | ○ | | 設定ID（settings.id） |
| tag_id | int | ○ | | タグID（tags.id） |
| created_at | datetime | ○ | | 作成日時 |

---

## インデックス

| インデックス名 | 種類 | 説明 | カラム |
|----------------|------|------|--------|
| PRIMARY KEY | 主キー | 関連IDの主キー | id |
| INDEX | 通常 | 設定検索用 | setting_id |
| INDEX | 通常 | タグ検索用 | tag_id |
| UNIQUE | 一意 | 設定・タグの重複防止 | setting_id, tag_id |

---

## 制約条件

### 主キー制約
- `id`: 自動採番（AUTO_INCREMENT）

### 外部キー制約
- `setting_id` → `settings.id`
- `tag_id` → `tags.id`

### 一意制約
- `setting_id`と`tag_id`の組み合わせは一意

---

## 設計補足

### 多対多関係
- 設定とタグの多対多関係を実現
- 中間テーブルによる関連管理

### 重複防止
- 同じ設定に同じタグを重複して付けることはできない
- 一意制約によりデータ整合性を保証

### パフォーマンス
- タグ検索の最適化のため適切なインデックスを設定
- 設定・タグの削除時の関連データ処理を考慮

---

## 関連テーブル

- `settings`: 多対1の関係（設定）
- `tags`: 多対1の関係（タグ）

---

## 運用上の注意点

1. **データ整合性**: 設定やタグが削除された場合の関連データの処理
2. **パフォーマンス**: 大量のタグ関連データに対する適切なインデックス設定
3. **重複防止**: 同じ設定・タグの組み合わせの重複登録防止
4. **検索最適化**: タグによる検索機能のパフォーマンス確保
