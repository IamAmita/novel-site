# 設定詳細テーブル（setting_details）

---

## 概要
設定の詳細情報（タイトル、説明、概要、キーワードなど）を管理するテーブル。`settings`テーブルと1対1の関係を持ち、設定の内容に関する情報を分離して管理することで、パフォーマンスと拡張性を向上させる。

---

## テーブル定義

| 属性名        | 型            | 必須 | 一意 | 説明                           |
|---------------|---------------|------|------|--------------------------------|
| id            | int           | ○    | ○    | 詳細ID（主キー）               |
| setting_id    | int           | ○    | ○    | 設定ID（外部キー）             |
| title         | varchar(255)  | ○    |      | 設定タイトル                   |
| description   | longtext      | ○    |      | 設定の内容（マークダウン対応） |
| summary       | text          |      |      | 設定の概要                     |
| keywords      | varchar(500)  |      |      | キーワード（カンマ区切り）      |
| created_at    | datetime      | ○    |      | 作成日時                       |
| updated_at    | datetime      | ○    |      | 更新日時                       |

---

## インデックス

| インデックス名           | 種類 | 説明               | カラム                |
|------------------------|------|-------------------|----------------------|
| PRIMARY KEY            | 主キー | 詳細IDの主キー     | id                   |
| UNIQUE                 | 一意 | 設定IDの一意制約   | setting_id           |
| INDEX                  | 通常 | タイトル検索用     | title                |
| INDEX                  | 通常 | キーワード検索用   | keywords             |
| INDEX                  | 通常 | 作成日時検索用     | created_at           |
| INDEX                  | 通常 | 更新日時検索用     | updated_at           |
| FULLTEXT               | 全文検索 | タイトル・説明・概要の全文検索用 | title, description, summary |

---

## 制約条件

### 主キー制約
- `id`: 自動採番（AUTO_INCREMENT）

### 一意制約
- `setting_id`: 設定IDは一意（1対1の関係）

### 外部キー制約
- `setting_id` → `settings.id`

### チェック制約
- `title`: 空文字列でないこと
- `description`: 空文字列でないこと

---

## 設計補足

### データ分離の目的
- **パフォーマンス向上**: 一覧表示時は`settings`のみ取得
- **拡張性**: 詳細情報の柔軟な追加が可能
- **権限管理**: 基本情報と詳細情報で異なる権限設定

### 1対1の関係
- 各設定は必ず1つの詳細情報を持つ
- 設定削除時は詳細情報も削除
- 設定作成時は詳細情報も同時作成

### 検索機能
- タイトルによる部分一致検索
- キーワードによるタグ検索
- 全文検索による内容検索

### 多言語対応の準備
- 将来的に言語別テーブルへの拡張が可能
- 現在は日本語のみ対応

---

## 関連テーブル

- `settings`: 1対1の関係（設定の基本情報）
- `setting_histories`: 1対多の関係（詳細情報の変更履歴）

---

## 運用上の注意点

1. **データ整合性**: 設定作成時は必ず詳細情報も作成
2. **検索最適化**: 全文検索インデックスの定期的な最適化
3. **キーワード管理**: キーワードの正規化と重複排除
4. **パフォーマンス**: 一覧表示時はJOINを避ける
5. **バックアップ**: 詳細情報の定期的なバックアップ
6. **監視**: 全文検索のパフォーマンス監視
