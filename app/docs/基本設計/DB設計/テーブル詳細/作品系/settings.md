# 設定テーブル（settings）

---

## 概要
小説投稿サイトの設定管理機能の基本情報を管理するテーブル。設定の詳細情報は`setting_details`テーブルで管理し、パフォーマンスと拡張性を向上させる。

---

## テーブル定義

| 属性名        | 型            | 必須 | 一意 | 説明                           |
|---------------|---------------|------|------|--------------------------------|
| id            | int           | ○    | ○    | 設定ID（主キー）               |
| user_id       | int           | ○    |      | 作成者ユーザーID（users.id）   |
| is_published  | tinyint(1)    | ○    |      | 公開フラグ（0:非公開, 1:公開） |
| created_at    | datetime      | ○    |      | 作成日時                       |
| updated_at    | datetime      | ○    |      | 更新日時                       |
| deleted_at    | datetime      |      |      | 論理削除日時                   |

---

## インデックス

| インデックス名           | 種類 | 説明               | カラム                |
|------------------------|------|-------------------|----------------------|
| PRIMARY KEY            | 主キー | 設定IDの主キー     | id                   |
| INDEX                  | 通常 | 作成者検索用       | user_id              |
| INDEX                  | 通常 | 公開状態検索用     | is_published         |
| INDEX                  | 通常 | 作成日時検索用     | created_at           |
| INDEX                  | 通常 | 更新日時検索用     | updated_at           |
| INDEX                  | 複合 | ユーザー・公開状態検索用 | user_id, is_published |

---

## 制約条件

### 主キー制約
- `id`: 自動採番（AUTO_INCREMENT）

### 外部キー制約
- `user_id` → `users.id`

### チェック制約
- `is_published` IN (0, 1)

---

## 設計補足

### データ分離の目的
- **パフォーマンス向上**: 一覧表示時は基本情報のみ取得
- **拡張性**: 詳細情報の柔軟な追加が可能
- **権限管理**: 基本情報と詳細情報で異なる権限設定

### 1対1の関係
- 各設定は必ず1つの詳細情報を持つ
- 設定削除時は詳細情報も削除
- 設定作成時は詳細情報も同時作成

### 基本情報管理
- 作成者、公開状態、日時などの基本情報
- 軽量で高速な検索・一覧表示
- 権限管理の基本単位

---

## 関連テーブル

- `setting_details`: 1対1の関係（設定の詳細情報）
- `setting_tags`: 多対多の関係（設定タグ）
- `setting_collaborators`: 1対多の関係（設定協作者）
- `setting_histories`: 1対多の関係（設定変更履歴）
- `setting_statuses`: 1対多の関係（設定ステータス）
- `user_permissions`: 多対多の関係（権限管理）
- `work_stats`: 1対1の関係（統計情報）
- `users`: 多対1の関係（作成者）

---

## 運用上の注意点

1. **データ整合性**: 設定作成時は必ず詳細情報も作成
2. **権限管理**: 権限の変更時は`user_permissions`テーブルで管理
3. **統計管理**: 統計情報の更新は`work_stats`テーブルで管理
4. **ステータス管理**: ステータス情報の更新は`setting_statuses`テーブルで管理
5. **パフォーマンス**: ユーザー・公開状態による効率的な検索
6. **データ整合性**: 関連設定・作品の存在確認
