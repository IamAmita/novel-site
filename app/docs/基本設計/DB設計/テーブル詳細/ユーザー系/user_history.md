# user_history テーブル詳細

---

## 概要
ユーザー情報の変更履歴を管理するテーブルです。変更種別、変更前後の値、変更理由、操作者などを含みます。

---

## テーブル定義

| 属性名         | 型         | 必須 | 一意 | 説明                         |
|----------------|------------|------|------|------------------------------|
| id             | int        | ○    | ○    | 履歴ID（主キー）             |
| user_id        | int        | ○    |      | ユーザーID（外部キー）       |
| type           | varchar    | ○    |      | 履歴種別（メール変更、ユーザー名変更、退会等） |
| before_value   | varchar    |      |      | 変更前の値                   |
| after_value    | varchar    |      |      | 変更後の値                   |
| reason         | text       |      |      | 変更・停止理由               |
| operated_by    | int        |      |      | 操作ユーザーID（管理者等）   |
| created_at     | datetime   | ○    |      | 登録日時                     |

---

## インデックス

| インデックス名 | 種類 | 説明 | カラム |
|----------------|------|------|--------|
| PRIMARY KEY | 主キー | 履歴IDの主キー | id |
| INDEX | 通常 | ユーザーID検索用 | user_id |
| INDEX | 通常 | 履歴種別検索用 | type |
| INDEX | 通常 | 操作者検索用 | operated_by |
| INDEX | 通常 | 登録日時検索用 | created_at |

---

## 制約条件

### 主キー制約
- `id`: 自動採番（AUTO_INCREMENT）

### 外部キー制約
- `user_id` → `users.id`: ユーザーテーブルを参照
- `operated_by` → `users.id`: 操作者ユーザーテーブルを参照

### チェック制約
- `type`: 'email_change', 'username_change', 'account_deletion', 'account_suspension'のいずれかである必要があります

---

## 設計補足

### ユーザーID（user_id）
- 変更が適用されたユーザー
- 存在するユーザーである必要があります

### 履歴種別（type）
- `email_change`: メールアドレス変更
- `username_change`: ユーザー名変更
- `account_deletion`: アカウント削除
- `account_suspension`: アカウント停止

### 変更前の値（before_value）
- 変更前の値
- 履歴追跡のために記録

### 変更後の値（after_value）
- 変更後の値
- 履歴追跡のために記録

### 変更理由（reason）
- 変更の詳細な理由
- 管理者による操作の場合は必須

### 操作者（operated_by）
- 変更を実行したユーザー
- 自己変更の場合はnull
- 管理者による操作の場合は管理者ID

---

## 関連テーブル

- `users`: 多対1の関係（変更対象ユーザー）
- `users`: 多対1の関係（操作者）

---

## 運用上の注意点

1. **履歴保持**: 重要な変更は必ず記録
2. **データ量**: 定期的なアーカイブ・削除が必要
3. **プライバシー**: 個人情報の適切な管理
4. **監査**: 管理者操作の履歴管理
