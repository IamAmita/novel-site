# user_profiles テーブル詳細

---

## 概要
ユーザーのプロフィール情報を管理するテーブルです。表示名、プロフィール画像、自己紹介などの公開情報を含みます。

---

## テーブル定義

| 属性名        | 型      | 必須 | 一意 | 説明                |
|---------------|---------|------|------|---------------------|
| id            | int     | ○    | ○    | プロフィールID      |
| user_id       | int     | ○    |      | ユーザーID（外部キー）|
| username      | varchar | ○    | ○    | ユーザー名           |
| profile_image | varchar |      |      | プロフィール画像URL |
| bio           | text    |      |      | 自己紹介            |
| interests     | text    |      |      | 興味・専門分野      |
| updated_at    | datetime|      |      | 更新日時            |

---

## インデックス

| インデックス名 | 種類 | 説明 | カラム |
|----------------|------|------|--------|
| PRIMARY KEY | 主キー | プロフィールIDの主キー | id |
| UNIQUE | 一意 | ユーザーIDの一意制約（1対1関係） | user_id |
| UNIQUE | 一意 | ユーザー名の一意制約 | username |
| INDEX | 通常 | 更新日時検索用 | updated_at |

---

## 制約条件

### 主キー制約
- `id`: 自動採番（AUTO_INCREMENT）

### 一意制約
- `user_id`: ユーザーIDは一意である必要があります（1対1関係）
- `username`: ユーザー名は一意である必要があります

### 外部キー制約
- `user_id` → `users.id`: ユーザーテーブルを参照

### チェック制約
- `username`: 空文字列は許可しない
- `profile_image`: URL形式である必要があります

---

## 設計補足

### ユーザー名（username）
- プロフィール情報で管理し、DBで一意制約
- 再利用不可が推奨
- ユーザー名の変更履歴は履歴テーブルで管理

### プロフィール画像
- S3等ストレージに保存し、URLのみ保持
- 未設定時はデフォルト画像URLを返す
- 画像サイズや形式の制限はアプリケーション側で管理

### 自己紹介（bio）
- テキスト形式で自由記入
- 文字数制限はアプリケーション側で管理
- HTMLタグ等の特殊文字はエスケープ処理

### 興味・専門分野（interests）
- テキスト形式で自由記入
- 将来的にはタグ形式への移行も検討

---

## 関連テーブル

- `users`: 多対1の関係（ユーザー基本情報）

---

## 運用上の注意点

1. **ユーザー名変更**: 履歴テーブルに記録
2. **プロフィール画像**: ストレージ容量の管理
3. **自己紹介**: 不適切な内容の監視
4. **データ整合性**: ユーザー削除時はプロフィールも削除
