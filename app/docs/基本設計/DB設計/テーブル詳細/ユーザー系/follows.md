# follows テーブル詳細

---

## 概要
ユーザー間のフォロー関係を管理するテーブルです。フォローするユーザー、フォローされるユーザー、フォロー日時などを含みます。

---

## テーブル定義

| 属性名         | 型         | 必須 | 一意 | 説明                         |
|----------------|------------|------|------|------------------------------|
| id             | int        | ○    | ○    | フォローID（主キー）         |
| follower_id    | int        | ○    |      | フォローするユーザーID       |
| followed_id    | int        | ○    |      | フォローされるユーザーID     |
| created_at     | datetime   | ○    |      | フォロー日時                 |

---

## インデックス

| インデックス名 | 種類 | 説明 | カラム |
|----------------|------|------|--------|
| PRIMARY KEY | 主キー | フォローIDの主キー | id |
| UNIQUE | 複合一意 | フォロー関係の一意制約 | follower_id, followed_id |
| INDEX | 通常 | フォローするユーザー検索用 | follower_id |
| INDEX | 通常 | フォローされるユーザー検索用 | followed_id |
| INDEX | 通常 | フォロー日時検索用 | created_at |

---

## 制約条件

### 主キー制約
- `id`: 自動採番（AUTO_INCREMENT）

### 一意制約
- `follower_id, followed_id`: フォロー関係は一意である必要があります

### 外部キー制約
- `follower_id` → `users.id`: フォローするユーザーテーブルを参照
- `followed_id` → `users.id`: フォローされるユーザーテーブルを参照

### チェック制約
- `follower_id` ≠ `followed_id`: 自分をフォローすることはできません

---

## 設計補足

### フォローするユーザー（follower_id）
- フォローを実行するユーザー
- 存在するユーザーである必要があります

### フォローされるユーザー（followed_id）
- フォローされるユーザー
- 存在するユーザーである必要があります

### フォロー日時（created_at）
- フォロー関係が成立した日時
- 履歴追跡のために記録

### 相互フォロー
- 相互フォローは2つのレコードで管理
- アプリケーション側で相互フォロー判定を実装

---

## 関連テーブル

- `users`: 多対1の関係（フォローするユーザー）
- `users`: 多対1の関係（フォローされるユーザー）

---

## 運用上の注意点

1. **自己フォロー**: 自分をフォローすることはできません
2. **重複フォロー**: 同じユーザーを複数回フォローすることはできません
3. **フォロー解除**: レコードの削除でフォロー解除
4. **相互フォロー**: アプリケーション側で判定ロジックを実装
5. **フォロー解除時は論理削除**
