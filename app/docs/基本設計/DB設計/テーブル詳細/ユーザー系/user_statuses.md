# user_statuses テーブル詳細

---

## 概要
ユーザーのステータス（状態）を管理するテーブルです。各ユーザーの現在のステータス（通常、一時停止、永久停止、警告中など）を記録し、ステータス変更の履歴も保持します。

---

## テーブル定義

| 属性名             | 型         | 必須 | 一意 | 説明                                 |
|--------------------|------------|------|------|--------------------------------------|
| id                 | int        | ○    | ○    | ステータス履歴ID（主キー）           |
| user_id            | int        | ○    |      | ユーザーID（外部キー）               |
| status_id          | tinyint    | ○    |      | ステータス定義ID（外部キー）         |
| created_at         | datetime   | ○    |      | ステータス変更日時                   |
| updated_at         | datetime   |      |      | 更新日時                             |

---

## インデックス

| インデックス名 | 種類 | 説明 | カラム |
|----------------|------|------|--------|
| PRIMARY KEY | 主キー | ステータス履歴IDの主キー | id |
| INDEX | 通常 | ユーザー検索用 | user_id |
| INDEX | 複合 | 現在のステータス検索用 | user_id, created_at |
| INDEX | 通常 | ステータス検索用 | status_id |
| INDEX | 通常 | 変更日時検索用 | created_at |

---

## 制約条件

### 主キー制約
- `id`: 自動採番（AUTO_INCREMENT）

### 外部キー制約
- `user_id` → `users.id`: ユーザーテーブルを参照
- `status_id` → `master_statuses.id`: ステータス定義テーブルを参照

### チェック制約
- `status_id`: 有効なステータス定義IDである必要があります

---

## 設計補足

### ステータスID（status_id）
- master_statusesテーブルで定義されたステータスのID
- ユーザー対象のステータス（target_type=1）を参照
- 例：0（active）、1（warned）、2（suspended）、3（banned）

### 現在のステータス管理
- 各ユーザーの最新のレコードが現在のステータス
- ステータス変更時は新しいレコードを作成
- 履歴として過去のステータスも保持

### 権限制御
- ステータスに応じた権限制御はアプリケーション側で実装
- master_statusesテーブルの定義に基づいて権限を判定

---

## ステータス例

| status_id | ステータス名 | 説明 |
|-----------|-------------|------|
| 0 | active | 通常ユーザー |
| 1 | warned | 警告中 |
| 2 | suspended | 一時停止 |
| 3 | banned | 永久停止 |

---

## 関連テーブル

- `users`: 多対1の関係（ユーザーのステータス管理）
- `master_statuses`: 多対1の関係（ステータス定義）
- `user_histories`: 1対多の関係（ステータス変更理由の履歴）

---

## 運用上の注意点

1. **ステータス変更**: 変更時は新しいレコードを作成
2. **権限制御**: アプリケーション側でステータスに応じた権限チェックを実施
3. **履歴管理**: ステータス変更の履歴を保持し、透明性を確保
4. **自動制限**: 被通報回数に応じた自動ステータス変更
5. **復旧処理**: 一時停止ユーザーの復旧手順を明確化
6. **パフォーマンス**: 現在のステータス取得は`user_id, created_at`の複合インデックスを活用
7. **変更理由**: ステータス変更の理由は`user_histories`テーブルで管理
