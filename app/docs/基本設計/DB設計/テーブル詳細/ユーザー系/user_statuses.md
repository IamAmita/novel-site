# user_statuses テーブル詳細（ユーザーステータス管理）

---

## 概要
ユーザーのステータス（状態）を管理するテーブルです。ユーザーのアカウント状態（通常、警告中、一時停止、永久停止など）を履歴として保持し、ステータス変更の透明性を確保します。

---

## テーブル定義

| 属性名           | 型      | 必須 | 一意 | 説明                                 |
|------------------|---------|------|------|--------------------------------------|
| id               | int     | ○    | ○    | ステータス履歴ID（主キー）           |
| user_id          | int     | ○    |      | ユーザーID（users.idを参照）         |
| status_id        | tinyint | ○    |      | ステータス定義ID（master_statuses.idを参照） |
| status_value     | tinyint | ○    |      | ステータス値（数値コード）           |
| created_at       | datetime| ○    |      | ステータス変更日時                   |
| updated_at       | datetime| ○    |      | 更新日時                             |
| deleted_at       | datetime|      |      | 削除日時                             |
| is_deleted       | tinyint | ○    |      | 削除フラグ（0：有効、1：削除済み、デフォルト：0） |

---

## インデックス

| インデックス名 | 種類   | 説明                   | カラム           |
|----------------|--------|------------------------|------------------|
| PRIMARY KEY    | 主キー | ステータス履歴IDの主キー | id               |
| UNIQUE         | 複合   | 1ユーザー1ステータスの重複防止 | user_id, status_id |
| INDEX          | 通常   | ユーザー検索用         | user_id          |
| INDEX          | 複合   | 現在のステータス検索用 | user_id, created_at |
| INDEX          | 通常   | ステータス検索用       | status_id        |
| INDEX          | 通常   | 変更日時検索用         | created_at       |
| INDEX          | 通常   | 削除フラグ検索用       | is_deleted       |

---

## 制約条件

### 主キー制約
- `id`: 自動採番（AUTO_INCREMENT）

### 外部キー制約
- `user_id` → `users.id`: ユーザーテーブルを参照
- `status_id` → `master_statuses.id`: ステータス定義テーブルを参照

### ユニーク制約
- `user_id, status_id`: 1ユーザーに同じステータスを重複登録不可

### チェック制約
- `status_id`: ユーザー用ステータス定義ID（401〜404）のみ許可
- `status_value`: 1〜255の範囲の数値のみ許可
- `is_deleted`: 0（有効）または1（削除済み）のみ許可、デフォルト値は0

---

## 設計補足

### ステータスID（status_id）
- master_statusesテーブルで定義されたユーザー用ステータスのID
- 401〜404の範囲で管理
- 例：401（active）、402（warned）、403（suspended）、404（banned）

### ステータス値（status_value）
- システム内部で使用する数値コード
- master_statusesのstatus_valueと同期を保つ
- アプリケーション側での判定に使用
- 1〜255の範囲で管理（tinyintの制限）

### 現在のステータス管理
- 各ユーザーの最新のレコードが現在のステータス
- ステータス変更時は新しいレコードを作成
- 履歴として過去のステータスも保持

### 権限制御
- ステータスに応じた権限制御はアプリケーション側で実装
- 警告中・停止中ユーザーの機能制限

### 論理削除
- 論理削除により、参照整合性を保ちながらデータの履歴を保持
- 削除されたレコードは通常の検索から除外
- is_deleted = 0：有効なレコード
- is_deleted = 1：削除済みレコード

---

## 運用上の注意点

1. **ステータス変更**: 変更時は新しいレコードを作成
2. **権限制御**: アプリケーション側でステータスに応じた権限チェックを実施
3. **履歴管理**: ステータス変更の履歴を保持し、透明性を確保
4. **パフォーマンス**: 現在のステータス取得は`user_id, created_at`の複合インデックスを活用
5. **データ整合性**: ユーザー削除時は関連するステータスレコードも論理削除
6. **論理削除**: 削除されたレコードは通常の検索から除外し、履歴として保持
7. **重複防止**: 複合一意制約により、1ユーザーに同じステータスの重複設定を防止
8. **自動変更**: 通報数による自動ステータス変更の仕組み
9. **復活処理**: 一時停止ユーザーの復活手続き

---

## ステータス変更フロー

### 手動変更（管理者）
1. 管理者がステータス変更を実行
2. 新しいレコードを作成
3. ユーザーに通知

### 自動変更（システム）
1. 通報数が閾値に達する
2. 自動的にステータス変更
3. 管理者に通知

### 復活処理
1. ユーザーからの復活申請
2. 管理者による審査
3. 承認時は新しいステータスレコード作成
4. ユーザーに復活通知
