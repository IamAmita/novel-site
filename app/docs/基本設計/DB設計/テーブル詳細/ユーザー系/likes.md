# likes テーブル詳細

---

## 概要
ユーザーが投稿したいいねを管理するテーブルです。いいねしたユーザー、対象種別、対象ID、いいね日時などを含みます。

---

## テーブル定義

| 属性名         | 型         | 必須 | 一意 | 説明                                 |
|----------------|------------|------|------|--------------------------------------|
| id             | int        | ○    | ○    | いいねID（主キー）                   |
| user_id        | int        | ○    |      | いいねしたユーザーID                 |
| target_type    | tinyint    | ○    |      | いいね対象分類（master_classesテーブル参照）                       |
| target_id      | int        | ○    |      | いいね対象ID                         |
| created_at     | datetime   | ○    |      | いいね日時                           |

---

## インデックス

| インデックス名 | カラム | 種類 | 説明 |
|----------------|--------|------|------|
| PRIMARY KEY | id | 主キー | いいねIDの主キー |
| UNIQUE | user_id, target_type, target_id | 複合一意 | ユーザー・対象の組み合わせ一意制約 |
| INDEX | user_id | 通常 | いいねしたユーザー検索用 |
| INDEX | target_type | 通常 | 対象種別検索用 |
| INDEX | target_id | 通常 | 対象ID検索用 |
| INDEX | created_at | 通常 | いいね日時検索用 |

---

## 制約条件

### 主キー制約
- `id`: 自動採番（AUTO_INCREMENT）

### 一意制約
- `user_id, target_type, target_id`: ユーザーと対象の組み合わせは一意である必要があります

### 外部キー制約
- `user_id` → `users.id`: いいねしたユーザーテーブルを参照
- `target_type` → `master_classes.id`: 分類定義テーブルを参照

### チェック制約
- `target_type`: 1、2、3のいずれかである必要があります

---

## 設計補足

### いいねしたユーザー（user_id）
- いいねを実行したユーザー
- 存在するユーザーである必要があります

### いいね対象分類（target_type, target_id）
- master_classesテーブルで定義された分類ID
- 例：1（小説）、2（設定）、3（話）など

### 対象ID（target_id）
- いいねが適用される具体的な対象のID
- 対象種別に応じて適切なテーブルを参照

### いいね日時（created_at）
- いいねが実行された日時
- 履歴追跡のために記録

---

## 関連テーブル

- `users`: 多対1の関係（いいねしたユーザー）
- `master_classes`: 多対1の関係（分類定義）

---

## 運用上の注意点

1. **論理削除**: is_deleted=1で削除済み、0で有効。全テーブルで統一。
2. **重複いいね防止**: 1ユーザーにつき1対象に1つのいいねのみ許可
3. **パフォーマンス**: 対象別のいいね数集計が高速
4. **データ整合性**: 重複いいねの防止
