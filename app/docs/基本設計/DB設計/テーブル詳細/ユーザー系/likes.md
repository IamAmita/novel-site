# likes テーブル詳細

---

## 概要
ユーザーが投稿したいいねを管理するテーブルです。いいねしたユーザー、対象種別、対象ID、いいね日時などを含みます。

---

## テーブル定義

| 属性名         | 型         | 必須 | 一意 | 説明                                 |
|----------------|------------|------|------|--------------------------------------|
| id             | int        | ○    | ○    | いいねID（主キー）                   |
| user_id        | int        | ○    |      | いいねしたユーザーID                 |
| target_type    | tinyint    | ○    |      | いいね対象種別                       |
| target_id      | int        | ○    |      | いいね対象ID                         |
| created_at     | datetime   | ○    |      | いいね日時                           |

---

## インデックス

| インデックス名 | カラム | 種類 | 説明 |
|----------------|--------|------|------|
| PRIMARY KEY | id | 主キー | いいねIDの主キー |
| UNIQUE | user_id, target_type, target_id | 複合一意 | ユーザー・対象の組み合わせ一意制約 |
| INDEX | user_id | 通常 | いいねしたユーザー検索用 |
| INDEX | target_type | 通常 | 対象種別検索用 |
| INDEX | target_id | 通常 | 対象ID検索用 |
| INDEX | created_at | 通常 | いいね日時検索用 |

---

## 制約条件

### 主キー制約
- `id`: 自動採番（AUTO_INCREMENT）

### 一意制約
- `user_id, target_type, target_id`: ユーザーと対象の組み合わせは一意である必要があります

### 外部キー制約
- `user_id` → `users.id`: ユーザーテーブルを参照
- `target_type` → `target_types.id`: 対象種別定義テーブルを参照

### チェック制約
- `target_type`: 1、2、3のいずれかである必要があります

---

## 設計補足

### いいねしたユーザー（user_id）
- いいねを実行したユーザー
- 存在するユーザーである必要があります

### 対象種別（target_type）
- `1`: 小説作品へのいいね
- `2`: 設定（世界観・キャラ等）へのいいね
- `3`: 話（エピソード）へのいいね

### 対象ID（target_id）
- いいねが適用される具体的な対象のID
- 対象種別に応じて適切なテーブルを参照

### いいね日時（created_at）
- いいねが実行された日時
- 履歴追跡のために記録

---

## 関連テーブル

- `users`: 多対1の関係（いいねしたユーザー）

---

## 運用上の注意点

1. **重複いいね**: 同じ対象に複数回いいねすることはできません
2. **いいね解除**: レコードの削除でいいね解除
3. **対象削除**: 対象が削除された場合のいいね処理
4. **パフォーマンス**: いいね数の集計クエリの最適化

- 重複いいねの防止
