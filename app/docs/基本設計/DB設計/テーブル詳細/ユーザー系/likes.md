# likes テーブル詳細

---

## 概要
ユーザーが投稿したいいねを管理するテーブルです。いいねしたユーザー、クラスID、対象テーブル、対象ID、いいね日時、論理削除フラグなどを含みます。

---

## テーブル定義

| 属性名         | 型         | 必須 | 一意 | 説明                                 |
|----------------|------------|------|------|--------------------------------------|
| id             | int        | ○    | ○    | いいねID（主キー）                   |
| user_id        | int        | ○    |      | いいねしたユーザーID                 |
| class_id       | int        | ○    |      | クラスID（master_classes参照）        |
| table_id       | int        | ○    |      | 対象テーブルID（master_tables参照）  |
| target_id      | int        | ○    |      | いいね対象ID                         |
| delete_flg     | tinyint    | ○    |      | 論理削除フラグ（0:有効, 1:削除済み） |
| created_at     | datetime   | ○    |      | いいね日時                           |

---

## インデックス

| インデックス名 | カラム | 種類 | 説明 |
|----------------|--------|------|------|
| PRIMARY KEY | id | 主キー | いいねIDの主キー |
| UNIQUE | user_id, class_id, table_id, target_id, delete_flg | 複合一意 | ユーザー・クラス・対象・削除フラグの組み合わせ一意制約 |
| INDEX | user_id | 通常 | いいねしたユーザー検索用 |
| INDEX | class_id | 通常 | クラスID検索用 |
| INDEX | table_id | 通常 | 対象テーブル検索用 |
| INDEX | target_id | 通常 | 対象ID検索用 |
| INDEX | delete_flg | 通常 | 論理削除フラグ検索用 |
| INDEX | created_at | 通常 | いいね日時検索用 |

---

## 制約条件

### 主キー制約
- `id`: 自動採番（AUTO_INCREMENT）

### 一意制約
- `user_id, class_id, table_id, target_id, delete_flg`: ユーザー・クラス・対象・削除フラグの組み合わせは一意である必要があります

### 外部キー制約
- `user_id` → `users.id`: いいねしたユーザーテーブルを参照
- `class_id` → `master_classes.id`: クラス定義マスタを参照
- `table_id` → `master_tables.id`: 対象テーブルマスタを参照

### チェック制約
- `delete_flg`: 0または1の値のみ許可（0:有効, 1:削除済み）

---

## 設計補足

### いいねしたユーザー（user_id）
- いいねを実行したユーザー
- 存在するユーザーである必要があります

### クラスID（class_id）
- master_classesテーブルで管理されているクラスIDを参照
- 対象の分類や種別を柔軟に管理可能

### 対象テーブルID（table_id）
- master_tablesテーブルで管理されているテーブルIDを参照
- どのテーブルのどのレコードに対するいいねかを明確に管理

### 対象ID（target_id）
- いいねが適用される具体的な対象のID
- 対象テーブル・クラスに応じて適切なテーブルを参照

### 論理削除フラグ（delete_flg）
- 0:有効、1:削除済みとして管理
- いいね解除時はdelete_flg=1に更新
- 履歴や監査のため物理削除は行わない

### いいね日時（created_at）
- いいねが実行された日時
- 履歴追跡のために記録

---

## 関連テーブル

- `users`: 多対1の関係（いいねしたユーザー）
- `master_classes`: 多対1の関係（クラス定義マスタ）
- `master_tables`: 多対1の関係（対象テーブルマスタ）

---

## 運用上の注意点

1. **論理削除**: delete_flg=1で削除済み、0で有効。全テーブルで統一。
2. **重複いいね防止**: 1ユーザーにつき1対象に1つのいいねのみ許可（delete_flg=0のみ有効）
3. **パフォーマンス**: 対象別のいいね数集計が高速
4. **データ整合性**: 重複いいねの防止
