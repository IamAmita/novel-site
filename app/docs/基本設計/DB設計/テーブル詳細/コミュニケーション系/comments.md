# comments テーブル詳細

---

## 概要
ユーザーが投稿したコメントを管理するテーブルです。多様な対象（小説・設定・話・掲示板の投稿など）にコメントでき、本文内で`>>番号`形式の返信指定とGood/Bad評価機能を含みます。コメント対象はclass_id（master_classes.id, 2桁:10〜99）とtable_id（master_tables.id, 4桁:1000〜9999）で管理します。

---

## テーブル定義

| 属性名             | 型         | 必須 | 一意 | 説明                                 |
|--------------------|------------|------|------|--------------------------------------|
| id                 | int        | ○    | ○    | コメントID（主キー）                 |
| user_id            | int        | ○    |      | 投稿者ユーザーID（外部キー）         |
| class_id           | int        | ○    |      | コメント対象クラスID（master_classes.id, 2桁:10〜99） |
| table_id    | int        | ○    |      | コメント対象テーブルID（master_tables.id, 4桁:1000〜9999） |
| target_id          | int        | ○    |      | コメント対象ID                       |
| body               | text       | ○    |      | コメント本文（>>番号で返信指定）     |
| is_deleted         | tinyint    | ○    |      | 通報による自動削除フラグ             |
| created_at         | datetime   | ○    |      | 作成日時                             |
| updated_at         | datetime   |      |      | 更新日時                             |

---

## インデックス

| インデックス名 | カラム | 種類 | 説明 |
|----------------|--------|------|------|
| PRIMARY KEY | id | 主キー | コメントIDの主キー |
| INDEX | user_id | 通常 | 投稿者検索用 |
| INDEX | class_id, table_id, target_id | 複合 | 対象検索用 |
| INDEX | is_deleted | 通常 | 削除状態検索用 |
| INDEX | created_at | 通常 | 作成日時検索用 |

---

## 制約条件

### 主キー制約
- `id`: 自動採番（AUTO_INCREMENT）

### 外部キー制約
- `user_id` → `users.id`: 投稿者ユーザーテーブルを参照
- `class_id` → `master_classes.id`: クラス種別マスタを参照
- `table_id` → `master_tables.id`: テーブル種別マスタを参照

### チェック制約
- `class_id`: 10〜99のいずれかである必要があります
- `table_id`: 1000〜9999のいずれかである必要があります
- `is_deleted`: 0または1のみ許可

---

## 設計補足

### コメント対象（class_id, table_id, target_id）
- master_classesテーブルで定義されたクラスID（例：10=小説、20=設定、30=話など）
- master_tablesテーブルで定義されたテーブルID（例：1001=novels, 2001=settings, 3001=episodesなど）
- target_idは対象テーブルの主キーID

### 通報管理
- `reports`テーブルからバッチ処理で通報数を集計
- 一定数（例：5回）で論理削除（is_deleted = 1）
- 手動承認は不要
- 通報は使用頻度が低く、リアルタイム性が重要でないためバッチ集計

### Good/Bad評価
- `comment_evaluations`テーブルからリアルタイムで集計
- 表示時にサーバー処理で評価数を計算
- キャッシュ機能でパフォーマンスを最適化
- 評価は使用頻度が高く、リアルタイム性が重要なためリアルタイム集計

### 論理削除（is_deleted）
- 通報による論理削除フラグ（0:有効、1:削除）
- 表示時は削除されていないコメントのみ表示
- 削除されたコメントへの返信は「このコメントは削除されました」と表示

## コメントの流れ例

| コメントID | 投稿者 | class_id | table_id | target_id | 本文 | 説明 |
|------------|--------|----------|-----------------|-----------|------|------|
| 1 | ユーザーA | 10 | 1001 | 1 | 面白い小説ですね！ | 小説へのコメント |
| 2 | ユーザーB | 10 | 1001 | 1 | >>1 ありがとうございます！ | コメント1への返信 |
| 3 | ユーザーC | 10 | 1001 | 1 | >>1 私も同感です！ | コメント1への返信 |
| 4 | ユーザーD | 10 | 1001 | 1 | 続きが楽しみです | 小説へのコメント |

### 表示例
```
小説1のコメント一覧：

1. ユーザーA: 面白い小説ですね！ [Good: 5, Bad: 1]
2. ユーザーB: >>1 ありがとうございます！ [Good: 3, Bad: 0]
3. ユーザーC: >>1 私も同感です！ [Good: 2, Bad: 1]
4. ユーザーD: 続きが楽しみです [Good: 1, Bad: 0]
```

## 関連テーブル

- `users`: 多対1の関係（投稿者）
- `master_classes`: 多対1の関係（クラス種別）
- `master_tables`: 多対1の関係（テーブル種別）
- `comment_evaluations`: 1対多の関係（評価履歴）
- `reports`: 1対多の関係（通報履歴）

---

## 運用上の注意点

1. **論理削除**: is_deleted=1で削除済み、0で有効。全テーブルで統一。
2. **編集・削除権限**: 投稿者または管理者のみ編集・削除可能
3. **通報管理**: 一定数の通報で自動削除
4. **履歴管理**: 削除・編集履歴は保持
5. **パフォーマンス**: 表示時は論理削除されていないコメントのみ抽出
6. **返信機能**: 本文内で`>>番号`指定、シンプルで直感的
7. **評価機能**: 表示時にリアルタイム集計、キャッシュで最適化
8. **バリデーション**: 指定された番号のコメントが存在するかチェック
9. **表示処理**: `>>番号`をリンクとして表示、クリックで該当コメントにジャンプ
10. **データ整合性**: 評価・通報ともに集計カラムを持たず、テーブルから集計
