# 世界情報テーブル（world_info）

---

## 概要
世界の詳細情報（タイトル、概要など）を管理するテーブル。`worlds`テーブルと1対1の関係を持ち、世界の内容に関する情報を分離して管理することで、パフォーマンスと拡張性を向上させる。

---

## テーブル定義

| 属性名        | 型            | 必須 | 一意 | 説明                           |
|---------------|---------------|------|------|--------------------------------|
| id            | int           | ○    | ○    | 情報ID（主キー）               |
| world_id      | int           | ○    | ○    | 世界ID（外部キー）             |
| title         | varchar(255)  | ○    |      | 世界タイトル                   |
| description   | longtext      | ○    |      | 世界概要（マークダウン対応）   |
| delete_flg    | tinyint(1)    | ○    |      | 削除フラグ（0:有効, 1:削除済み） |
| created_at    | datetime      | ○    |      | 作成日時                       |
| updated_at    | datetime      | ○    |      | 更新日時                       |
| deleted_at    | datetime      |      |      | 削除日時                       |

---

## インデックス

| インデックス名           | 種類 | 説明               | カラム                |
|------------------------|------|-------------------|----------------------|
| PRIMARY KEY            | 主キー | 情報IDの主キー     | id                   |
| UNIQUE                 | 一意 | 世界IDの一意制約   | world_id             |
| INDEX                  | 通常 | タイトル検索用     | title                |
| INDEX                  | 通常 | 削除フラグ検索用   | delete_flg           |
| INDEX                  | 通常 | 作成日時検索用     | created_at           |
| INDEX                  | 通常 | 更新日時検索用     | updated_at           |
| INDEX                  | 通常 | 削除日時検索用     | deleted_at           |
| FULLTEXT               | 全文検索 | タイトル・概要の全文検索用 | title, description |

---

## 制約条件

### 主キー制約
- `id`: 自動採番（AUTO_INCREMENT）

### 一意制約
- `world_id`: 世界IDは一意（1対1の関係）

### 外部キー制約
- `world_id` → `worlds.id`

### チェック制約
- `title`: 空文字列でないこと
- `description`: 空文字列でないこと
- `delete_flg` IN (0, 1)

---

## 設計補足

### データ分離の目的
- **パフォーマンス向上**: 一覧表示時は`worlds`のみ取得
- **拡張性**: 詳細情報の柔軟な追加が可能
- **権限管理**: 基本情報と詳細情報で異なる権限設定

### 1対1の関係
- 各世界は必ず1つの詳細情報を持つ
- 世界削除時は詳細情報も削除
- 世界作成時は詳細情報も同時作成

### 検索機能
- タイトルによる部分一致検索
- 全文検索による概要検索

### 多言語対応の準備
- 将来的に言語別テーブルへの拡張が可能
- 現在は日本語のみ対応

### 論理削除
- `delete_flg`で論理削除を実現
- `deleted_at`で削除日時を記録
- 削除された詳細情報は通常の検索から除外

---

## 関連テーブル

- `worlds`: 1対1の関係（世界の基本情報）
- `setting_histories`: 1対多の関係（詳細情報の変更履歴）

---

## 運用上の注意点

1. **データ整合性**: 世界作成時は必ず詳細情報も作成
2. **検索最適化**: 全文検索インデックスの定期的な最適化
3. **パフォーマンス**: 一覧表示時はJOINを避ける
4. **バックアップ**: 詳細情報の定期的なバックアップ
5. **監視**: 全文検索のパフォーマンス監視
6. **論理削除**: 削除された詳細情報の適切な処理
7. **削除日時管理**: 削除日時の正確な記録
