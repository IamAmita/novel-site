# 統合カテゴリテーブル（categories）

---

## 概要
設定で使用するカテゴリを統合管理するテーブル。運営作成のシステムカテゴリとユーザー作成の独自カテゴリを1つのテーブルで管理し、階層構造による柔軟な分類を提供する。作成者種別による権限管理により、運営カテゴリの保護とユーザーカテゴリの自由な管理を実現する。

---

## テーブル定義

| 属性名           | 型            | 必須 | 一意 | 説明                                     |
|------------------|---------------|------|------|------------------------------------------|
| id               | int           | ○    | ○    | カテゴリID（主キー）                     |
| name             | varchar(100)  | ○    |      | カテゴリ名                               |
| description      | text          |      |      | カテゴリの説明                           |
| creator_type     | tinyint       | ○    |      | 作成者種別（0:運営, 1:ユーザー）         |
| created_by       | int           |      |      | 作成者ID                                |
| parent_id        | int           |      |      | 親カテゴリID（階層構造用）               |
| level            | int           | ○    |      | 階層レベル（0:ルート, 1以上:サブ階層）   |
| is_active        | tinyint(1)    | ○    |      | アクティブフラグ（0:非アクティブ, 1:アクティブ） |
| created_at       | datetime      | ○    |      | 作成日時                                 |
| updated_at       | datetime      | ○    |      | 更新日時                                 |

---

## インデックス

| インデックス名                    | 種類 | 説明               | カラム                |
|----------------------------------|------|-------------------|----------------------|
| PRIMARY KEY                     | 主キー | カテゴリIDの主キー | id                   |
| INDEX                           | 通常 | 作成者種別検索用   | creator_type          |
| INDEX                           | 通常 | 作成者検索用       | created_by            |
| INDEX                           | 通常 | 親カテゴリ検索用   | parent_id             |
| INDEX                           | 通常 | 階層レベル検索用   | level                 |
| INDEX                           | 通常 | アクティブ検索用   | is_active             |
| INDEX                           | 通常 | 作成日時検索用     | created_at            |
| INDEX                           | 複合 | 作成者種別・アクティブ検索用 | creator_type, is_active |
| INDEX                           | 複合 | 親カテゴリ・レベル検索用 | parent_id, level |

---

## 制約条件

### 主キー制約
- `id`: 自動採番（AUTO_INCREMENT）

### 外部キー制約
- `created_by` → `users.id`
- `parent_id` → `categories.id` (自己参照)

### チェック制約
- `creator_type` IN (0, 1)
- `level` >= 0
- `is_active` IN (0, 1)

---

## 設計補足

### 作成者種別による権限管理
- **運営カテゴリ** (`creator_type = 0`): 運営が作成、編集・削除不可、保護対象
- **ユーザーカテゴリ** (`creator_type = 1`): ユーザーが作成、作成者のみ編集・削除可能
- 権限チェックは作成者種別と作成者IDで判定

### 階層構造管理
- `parent_id`と`level`を使用して階層構造を実現
- 標準的な階層構造管理方式
- 無制限階層のサポート（アプリケーション側で深さ制限）

### 階層レベルの例
- ルートカテゴリ: `level = 0`
- 第1階層: `level = 1`
- 第2階層: `level = 2`
- 第3階層: `level = 3`

### アクティブ状態管理
- `is_active`で論理削除を実現
- 非アクティブカテゴリは表示・検索対象外
- 関連設定への影響を考慮した削除処理

---

## 権限管理ルール

### 運営カテゴリ（creator_type = 0）
- **作成**: 運営のみ
- **編集**: 不可（保護対象）
- **削除**: 不可（保護対象）
- **閲覧**: 全ユーザー
- **階層移動**: 不可

### ユーザーカテゴリ（creator_type = 1）
- **作成**: 全ユーザー
- **編集**: 作成者のみ
- **削除**: 作成者のみ（子カテゴリがない場合）
- **閲覧**: 全ユーザー
- **階層移動**: 作成者のみ

---

## 関連テーブル

- `setting_categories`: 1対多の関係（設定へのカテゴリ適用）
- `users`: 多対1の関係（カテゴリ作成者）

---

## 運用上の注意点

1. **権限管理**: 作成者種別に応じた適切な権限チェック
2. **階層構造**: 階層の深さ制限と循環参照の防止
3. **データ整合性**: カテゴリ削除時の関連設定への影響
4. **パフォーマンス**: 適切なインデックス設計
5. **運営カテゴリの保護**: 誤削除・誤編集の防止
6. **階層移動**: 子カテゴリのレベル更新処理
7. **アクティブ状態**: 非アクティブカテゴリの適切な処理

---

## 注意事項

1. **作成者種別**: 運営カテゴリとユーザーカテゴリの明確な区別
2. **階層構造**: 標準的な階層クエリの実現
3. **権限管理**: シンプルで確実な権限制御
4. **パフォーマンス**: 適切なインデックス設計
5. **データ保護**: 運営カテゴリの安全性確保
6. **拡張性**: 将来的な機能追加への対応
