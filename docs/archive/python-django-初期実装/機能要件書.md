### F-101 ユーザー登録

**概要**: 未登録者がメールアドレス・ユーザー名・パスワードを使って新規アカウントを作成する。

**アクター**: ゲスト

**前提条件**: ログインしていない状態

**正常系フロー**:
1. ゲストが登録フォーム（`/register`）を開く
2. ユーザー名・メールアドレス・パスワードを入力し、利用規約に同意する
3. 「登録」ボタンを押す
4. システムが入力値をバリデーションする
5. ユーザーレコード・プロフィールレコードを作成し、デフォルト権限（読者）を付与する
6. JWT アクセストークン・リフレッシュトークンを発行して返す
7. ユーザーはログイン済み状態でトップページへ遷移する

**異常系 / バリデーション**:

| 条件 | メッセージ例 |
|------|------------|
| ユーザー名が規則外（長さ・使用文字） | 「ユーザー名は3〜20文字の英数字・ハイフンで入力してください」 |
| ユーザー名が既に使用中 | 「このユーザー名はすでに使われています」 |
| メールアドレスの形式が不正 | 「メールアドレスの形式が正しくありません」 |
| メールアドレスが既に登録済み | 「このメールアドレスはすでに登録されています」 |
| パスワードが要件を満たさない | 「パスワードは8文字以上で英字・数字・記号を含めてください」 |
| 利用規約に未同意 | 「登録」ボタンを非活性にして操作を阻止する |

**入力仕様**:

| フィールド | 型 | 必須 | 制約 |
|-----------|---|------|------|
| `username` | string | ○ | 3〜20文字、英字・数字・ハイフン（`-`）のみ、一意 |
| `email` | string | ○ | メール形式（RFC 5322）、254文字以内、一意 |
| `password` | string | ○ | 8文字以上、英字・数字・記号をそれぞれ1文字以上含む |
| `agreed_to_terms` | boolean | ○ | `true` でなければ登録不可 |

**出力仕様**:

```json
{
  "access": "<JWT アクセストークン>",
  "refresh": "<JWT リフレッシュトークン>",
  "user": { "id": 1, "username": "novel_user", "email": "user@example.com" }
}
```

**関連ビジネスルール**: BR-001, BR-002, BR-003, BR-004
**関連機能**: F-102（ログイン）

### F-102 ログイン / ログアウト

**概要**: 登録済みユーザーが認証を行い、JWT を取得してログイン状態になる。ログアウト時はリフレッシュトークンを無効化する。

**アクター**: ゲスト（ログイン）、読者 / 作者 / 管理者（ログアウト）

**前提条件（ログイン）**: 登録済みアカウントが存在し、アカウントが停止状態でないこと

**正常系フロー（ログイン）**:
1. ゲストがログインフォーム（`/login`）を開く
2. メールアドレスとパスワードを入力して「ログイン」を押す
3. システムが認証情報を検証する
4. JWT アクセストークン・リフレッシュトークンを発行して返す
5. ユーザーは直前にいたページまたはトップページへ遷移する

**正常系フロー（ログアウト）**:
1. ログイン済みユーザーが「ログアウト」を押す
2. システムがリフレッシュトークンをブラックリストに追加する
3. クライアント側のトークンを削除する
4. ゲスト状態でトップページへ遷移する

**正常系フロー（トークンリフレッシュ）**:
1. アクセストークンが期限切れ（401 レスポンス）を検知する
2. リフレッシュトークンを使って新しいアクセストークンを取得する
3. 元のリクエストを再実行する

**異常系 / バリデーション**:

| 条件 | 動作 |
|------|------|
| メールアドレスまたはパスワードが誤り | 「メールアドレスまたはパスワードが正しくありません」（どちらが誤りかは明示しない） |
| ログイン失敗5回 | アカウントをロック（`user_statuses` に記録）、ロック通知メールを送信 |
| アカウントが停止中 | 「アカウントが停止されています。サポートにお問い合わせください」 |
| リフレッシュトークン期限切れ | 401 を返し、再ログインを要求する |

**入力仕様（ログイン）**:

| フィールド | 型 | 必須 | 制約 |
|-----------|---|------|------|
| `email` | string | ○ | メール形式 |
| `password` | string | ○ | - |

**出力仕様（ログイン）**:

```json
{
  "access": "<JWT アクセストークン（有効期限: 30分）>",
  "refresh": "<JWT リフレッシュトークン（有効期限: 7日）>",
  "user": { "id": 1, "username": "novel_user" }
}
```

**関連ビジネスルール**: BR-504, BR-008
**関連機能**: F-101（ユーザー登録）

### F-103 プロフィール表示

**概要**: ユーザーの公開プロフィール情報と投稿作品一覧を表示する。

**アクター**: ゲスト / 読者 / 作者 / 管理者（全員閲覧可）

**前提条件**: 指定ユーザーが存在し、論理削除されていないこと

**正常系フロー**:
1. アクターがプロフィールページ（`/users/:id`）にアクセスする
2. システムがユーザー情報・プロフィール情報・公開作品一覧を返す
3. 表示名・アイコン・自己紹介・作品一覧・フォロワー数などを表示する

**異常系**:

| 条件 | 動作 |
|------|------|
| ユーザーが存在しない | 404 ページを表示する |
| ユーザーが論理削除済み | 404 ページを表示する（削除済みユーザーとして特定されないようにする） |

**出力仕様**:

```json
{
  "id": 1,
  "username": "novel_user",
  "profile": {
    "display_name": "小説太郎",
    "icon_url": "https://...",
    "biography": "自己紹介テキスト"
  },
  "stats": {
    "novel_count": 5,
    "follower_count": 120,
    "following_count": 30
  },
  "created_at": "2025-03-01T12:00:00+09:00"
}
```

**関連ビジネスルール**: BR-505（メールアドレスは非公開）
**関連機能**: F-104（プロフィール編集）

### F-104 プロフィール編集

**概要**: ログイン済みユーザーが自身のプロフィール情報を更新する。

**アクター**: 読者 / 作者 / 管理者（本人のみ）

**前提条件**: ログイン済み、かつ対象プロフィールが自分のものであること

**正常系フロー**:
1. ユーザーがプロフィール編集ページ（`/settings/profile`）を開く
2. 表示名・自己紹介・アイコン画像・WebサイトURL を編集する
3. 「保存」を押す
4. システムがバリデーションを行い、`user_profiles` レコードを更新する
5. 更新完了メッセージを表示する

**異常系 / バリデーション**:

| 条件 | メッセージ例 |
|------|------------|
| 表示名が空または長すぎる | 「表示名は1〜50文字で入力してください」 |
| 自己紹介が長すぎる | 「自己紹介は1,000文字以内で入力してください」 |
| アイコン画像がサイズ超過 | 「画像は10MB以内でアップロードしてください」 |
| アイコン画像が非対応形式 | 「JPEG・PNG・GIF・WebP 形式の画像を選択してください」 |

**入力仕様**:

| フィールド | 型 | 必須 | 制約 |
|-----------|---|------|------|
| `display_name` | string | ○ | 1〜50文字 |
| `biography` | string | - | 1,000文字以内 |
| `icon_image` | file | - | JPEG / PNG / GIF / WebP、10MB以内 |
| `website_url` | string | - | URL 形式、500文字以内 |

**関連ビジネスルール**: BR-607（画像10MB以内）
**関連機能**: F-103（プロフィール表示）

### F-105 パスワード変更

**概要**: ログイン済みユーザーが現在のパスワードを確認したうえで新しいパスワードに変更する。

**アクター**: 読者 / 作者 / 管理者（本人のみ）

**前提条件**: ログイン済みであること

**正常系フロー**:
1. ユーザーがセキュリティ設定ページ（`/settings/security`）を開く
2. 現在のパスワード・新しいパスワード・新しいパスワード（確認）を入力する
3. 「変更」を押す
4. 現在のパスワードが一致することを確認する
5. 新しいパスワードをハッシュ化して保存する
6. 全デバイスのリフレッシュトークンを無効化する
7. 変更完了メッセージを表示し、再ログインを促す

**異常系 / バリデーション**:

| 条件 | メッセージ例 |
|------|------------|
| 現在のパスワードが誤り | 「現在のパスワードが正しくありません」 |
| 新しいパスワードが要件を満たさない | 「パスワードは8文字以上で英字・数字・記号を含めてください」 |
| 新しいパスワードと確認が不一致 | 「パスワードが一致しません」 |
| 新しいパスワードが現在と同一 | 「現在と異なるパスワードを設定してください」 |

**入力仕様**:

| フィールド | 型 | 必須 | 制約 |
|-----------|---|------|------|
| `current_password` | string | ○ | - |
| `new_password` | string | ○ | 8文字以上、英字・数字・記号含む |
| `new_password_confirm` | string | ○ | `new_password` と一致 |

**関連ビジネスルール**: BR-003, BR-502
**関連機能**: F-102（ログイン）

### F-106 アカウント削除

**概要**: ユーザーが自身のアカウントを削除する。削除後30日間はデータを保持し、その後完全削除する。

**アクター**: 読者 / 作者 / 管理者（本人のみ）

**前提条件**: ログイン済みであること

**正常系フロー**:
1. ユーザーがアカウント設定ページから削除手続きを開始する
2. システムが削除内容の説明（投稿作品・コメントなども削除されること）を表示する
3. ユーザーが「削除する」ボタンを押す（確認ダイアログあり）
4. 現在のパスワードを入力して本人確認する
5. `users` テーブルの `deleted_at` に現在日時を設定する（論理削除）
6. 全リフレッシュトークンを無効化し、ログアウトする
7. 30日後のバッチ処理で完全削除（`user_id` に紐づく全データ）を実行する

**異常系 / バリデーション**:

| 条件 | 動作 |
|------|------|
| パスワードが誤り | 「パスワードが正しくありません」を表示し、削除を中断する |

**30日後の完全削除対象**:
- ユーザー本人の全データ（`users`、`user_profiles` 等）
- 投稿した小説・章・話（物理削除）
- 投稿したコメント（本文を「[退会済みユーザー]」に置換し、ユーザー紐づけを解除）
- フォロー・ブロック関係
- 通知

**関連ビジネスルール**: BR-503, BR-508
**関連機能**: F-102（ログイン）

### F-107 権限管理（管理者操作）

**概要**: 管理者がユーザーに対して権限の付与・剥奪、アカウントの停止・解除を行う。

**アクター**: 管理者

**前提条件**: 管理者権限でログイン済みであること

**正常系フロー（権限付与）**:
1. 管理者がユーザー管理画面を開き、対象ユーザーを選択する
2. 権限（読者・作者・管理者）を選択し「付与」を押す
3. `user_permissions` テーブルにレコードを追加する
4. `operation_histories` に操作ログを記録する

**正常系フロー（アカウント停止）**:
1. 管理者が対象ユーザーを選択し、停止理由を選択して「停止」を押す
2. `user_statuses` テーブルに停止レコードを追加する
3. 対象ユーザーの全リフレッシュトークンを無効化する
4. `operation_histories` に操作ログを記録する

**関連ビジネスルール**: BR-005, BR-006, BR-007, BR-008
**関連機能**: F-108（作者権限申請）

### F-108 作者権限申請

**概要**: 読者権限のユーザーが作者権限を申請し、管理者が承認・却下する。承認されると小説投稿が可能になる。

**アクター**: 読者（申請）、管理者（承認・却下）

**前提条件**: ログイン済み・読者権限のユーザーであること（申請側）

**正常系フロー（申請）**:
1. 読者がアカウント設定から「作者申請」を押す
2. 申請理由・利用目的を入力して送信する
3. システムが申請レコードを作成し、管理者に通知を送る
4. 審査中の旨を表示する

**正常系フロー（承認）**:
1. 管理者が申請一覧を確認し、承認または却下を選択する
2. 承認時は `user_permissions` に作者権限を追加する
3. 申請者に承認 / 却下の通知を送る
4. `operation_histories` に記録する

**異常系**:

| 条件 | 動作 |
|------|------|
| 既に申請中 | 「現在審査中です」を表示し、再申請を防ぐ |
| 既に作者権限を持つ | 申請ボタンを非表示にする |

**関連ビジネスルール**: BR-005, BR-006
**関連機能**: F-107（権限管理）

### F-201 小説投稿

**概要**: 作者権限を持つユーザーが新しい小説を作成する。作成直後は「下書き」状態となる。

**アクター**: 作者

**前提条件**: 作者権限でログイン済みであること

**正常系フロー**:
1. 作者が小説作成ページ（`/novels/create`）を開く
2. タイトル・あらすじ・カテゴリ・タグ・成人向けフラグを入力する
3. 「作成」を押す
4. システムが `novels`・`novel_info`・`novel_statuses` レコードを作成する（ステータス: 下書き）
5. 作成した小説の管理ページ（`/novels/:id/manage`）へ遷移する

**異常系 / バリデーション**:

| 条件 | メッセージ例 |
|------|------------|
| タイトルが空 | 「タイトルを入力してください」 |
| タイトルが100文字超 | 「タイトルは100文字以内で入力してください」 |
| あらすじが1,000文字超 | 「あらすじは1,000文字以内で入力してください」 |
| タグを11個以上指定 | 「タグは10個以内で設定してください」 |

**入力仕様**:

| フィールド | 型 | 必須 | 制約 |
|-----------|---|------|------|
| `title` | string | ○ | 1〜100文字 |
| `synopsis` | string | - | 1,000文字以内 |
| `category_id` | integer | - | 有効なカテゴリ ID |
| `tag_ids` | integer[] | - | 最大10個 |
| `is_r18` | boolean | ○ | デフォルト: `false` |

**公開ステータスの遷移**:

```
作成
  └→ [下書き] ──→ [公開]
                 └→ [限定公開]
                 └→ [非公開]  ←→  [公開]
  ※ 凍結（管理者のみ実施可能）
```

**関連ビジネスルール**: BR-101, BR-102, BR-107, BR-109
**関連機能**: F-202（小説編集）、F-205（話管理）、F-207（公開状態管理）

### F-202 小説編集

**概要**: 作品オーナーが小説の基本情報（タイトル・あらすじ・カテゴリ・タグ等）を更新する。

**アクター**: 作品オーナー

**前提条件**: ログイン済みかつ対象小説の作者本人であること

**正常系フロー**:
1. 作品オーナーが小説編集ページ（`/novels/:id/edit`）を開く
2. 変更したい項目を編集して「保存」を押す
3. システムが `novel_info` レコードを更新する

**異常系**:

| 条件 | 動作 |
|------|------|
| 他ユーザーが編集 URL に直接アクセス | 403 エラーを返す |
| 存在しない小説 ID | 404 エラーを返す |

**入力仕様**: F-201 と同様（全フィールドが任意更新可能）

**関連ビジネスルール**: BR-111
**関連機能**: F-201（小説投稿）

### F-203 小説削除

**概要**: 作品オーナーが小説を論理削除する。削除した小説は一覧・検索から除外され、30日後に完全削除される。

**アクター**: 作品オーナー、管理者

**前提条件**: ログイン済みかつ対象小説の作者本人または管理者であること

**正常系フロー**:
1. 小説管理ページで「削除」を押す
2. 確認ダイアログ（「削除すると元に戻せません。削除しますか？」）を表示する
3. 確認後、`novels` の `deleted_at` に現在日時を設定する（論理削除）
4. 紐づく章・話・設定も同時に論理削除する
5. キャッシュを削除する
6. 小説一覧ページへリダイレクトする

**関連ビジネスルール**: BR-111, BR-114, BR-503
**関連機能**: F-201（小説投稿）

### F-204 章管理

**概要**: 作品オーナーが章（Section）の作成・編集・削除・並べ替えを行う。

**アクター**: 作品オーナー

**前提条件**: ログイン済みかつ対象小説の作者本人であること

**正常系フロー（作成）**:
1. 管理ページで「章を追加」を押す
2. 章タイトルを入力して「追加」を押す
3. `sections` レコードを作成する（`sort_order` は末尾）

**正常系フロー（並べ替え）**:

### F-206 ルビ対応

**概要**: 話の本文中にルビ記法（`彼|かれ`）が含まれる場合、HTML の `<ruby>` タグに変換して表示する。

**アクター**: ゲスト / 読者 / 作者 / 管理者（閲覧者全員）

**前提条件**: 話本文にルビ記法が含まれていること

**記法仕様**:

| 記法 | 変換後 HTML | 表示 |
|------|-----------|------|
| `彼\|かれ` | `<ruby>彼<rt>かれ</rt></ruby>` | 彼（かれ） |
| `薔薇\|ばら` | `<ruby>薔薇<rt>ばら</rt></ruby>` | 薔薇（ばら） |
| `｜彼\|かれ` | 縦棒はエスケープとして扱い変換しない | `彼|かれ` |

**処理方針**:
- バックエンドで本文保存時にサニタイズのみ行い、ルビ変換はフロントエンドで実施する
- ルビ記法のパースは正規表現 `([^\|]+)\|([^\s\|]+)` を使用する
- ルビのないテキストへの影響がないように処理する

**関連機能**: F-205（話管理）、F-403（話閲覧）

### F-207 公開状態管理

**概要**: 作品オーナーが小説・話の公開状態を管理する。

**アクター**: 作品オーナー

**前提条件**: ログイン済みかつ対象の作者本人であること

**ステータス定義**:

| ステータス | 定数値 | 閲覧可能者 | 説明 |
|----------|--------|-----------|------|
| 下書き | `draft` | 作者本人のみ | 作成直後のデフォルト状態 |
| 公開 | `published` | 全ユーザー（未ログインも含む） | 一般公開 |
| 限定公開 | `limited` | 作者本人 + URLを知っている者 | リンク共有のみで公開 |
| 非公開 | `private` | 作者本人のみ | 公開停止 |
| 凍結 | `frozen` | 作者本人（読み取りのみ）| 管理者が規約違反時に設定 |

**ステータス遷移ルール**:

```
[下書き] → [公開] → [非公開] → [公開]（繰り返し可）
[下書き] → [限定公開]
[公開]   → [限定公開]
※ 凍結への遷移は管理者のみ実施可能
※ 凍結からの解除も管理者のみ実施可能
```

**話のステータスと小説ステータスの関係**:
- 小説が「下書き」の場合、全話はログインしていない状態で閲覧不可
- 話のステータスが「公開」でも、小説が「下書き」であれば閲覧不可
- 小説を「公開」にした場合、「公開」状態の話のみが閲覧可能

**関連ビジネスルール**: BR-104, BR-105, BR-106, BR-111, BR-114
**関連機能**: F-201（小説投稿）、F-205（話管理）
