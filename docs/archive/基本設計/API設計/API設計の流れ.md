# API設計の流れ

本ドキュメントでは、小説投稿サイトにおけるAPI設計の進め方・手順をまとめます。

---

## 1. API設計の方針決定
- RESTful設計を基本とする
- URL命名規則やバージョニングの決定（例：/api/v1/）
- 認証方式・レスポンス形式の統一（例：JWT認証、JSON形式）

## 2. リソース（エンティティ）の洗い出し
- テーブル設計・要件定義からAPIで扱う主要なリソースを抽出
  - 例：ユーザー、作品、小説、章、話、コメント、設定、通知、権限 など

## 3. ユースケース・画面フローの整理
- どの画面・機能でどんなデータが必要かを簡単に洗い出す
- 例：新規登録画面→POST /users、作品詳細画面→GET /novels/{id}

## 4. コア機能のAPI設計から着手
- まずは「ユーザー認証・管理」「小説投稿・閲覧」など、基本機能のAPI設計から始める
- 例：
  - POST /users（ユーザー登録）
  - POST /auth/login（ログイン）
  - GET /novels（小説一覧）
  - POST /novels（小説投稿）

## 5. エンドポイントごとに詳細設計
- 必要なパラメータ、返却データ、バリデーション、エラーケースなどを設計

## 6. API設計書としてまとめる
- OpenAPI（Swagger）やMarkdownでAPI設計書を作成
- チームや将来の自分が見て分かりやすい形にまとめる

---

まずはコアとなるリソースのCRUD API設計から始め、段階的に周辺機能のAPI設計へと広げていくことを推奨します。
