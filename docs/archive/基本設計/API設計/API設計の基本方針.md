# API設計の基本方針（たたき台）

本ドキュメントは、小説投稿サイトのAPI設計における基本方針のたたき台です。今後の議論・詳細化の出発点とします。

---

## 1. 設計スタイル
- RESTful API設計を基本とする
- リソースごとにエンドポイントを設計

## 2. エンドポイント命名規則
- すべてのAPIは `/api/v1/` から始める
- リソース名は複数形（例：/users, /novels）
- サブリソースは階層構造で表現（例：/novels/{novel_id}/episodes）

## 3. 認証・認可
- JWT（JSON Web Token）による認証を採用
- 認証が必要なAPIは Authorizationヘッダーでトークンを送信
- 一部のAPIは未認証でも利用可能（例：新規登録、ログイン）

## 4. リクエスト・レスポンス形式
- すべてJSON形式とする
- 日付はISO8601文字列（例：2025-01-01T12:00:00Z）
- 数値・真偽値は適切な型で返却

## 5. エラー仕様
- エラー時はHTTPステータスコードを適切に設定
- レスポンス例：
  ```json
  {
    "status": "error",
    "message": "エラーメッセージ",
    "code": 400
  }
  ```

## 6. ページネーション・フィルタ
- 一覧取得APIは limit/offset 方式のページネーションを採用
- クエリパラメータ例：?limit=20&offset=0
- ソート・フィルタはクエリパラメータで指定

## 7. セキュリティ
- すべての通信はHTTPSを前提
- CSRF/XSS等の基本的な対策を実施
- レートリミットやAPIキーの導入も検討

## 8. その他
- ファイルアップロードは multipart/form-data 方式
- OpenAPI（Swagger）によるAPIドキュメント化を推奨
