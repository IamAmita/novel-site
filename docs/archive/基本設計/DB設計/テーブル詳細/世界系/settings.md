# 設定テーブル（settings）

---

## 概要
設定の内容（タイトルなど）を管理するテーブル。`worlds`テーブルと1対1の関係を持ち、設定の内容に関する情報を分離して管理することで、パフォーマンスと拡張性を向上させる。

---

## テーブル定義

| 属性名        | 型            | 必須 | 一意 | 説明                           |
|---------------|---------------|------|------|--------------------------------|
| id            | int           | ○    | ○    | 設定ID（主キー）               |
| parent_id     | int           | ○    |      | 世界カテゴリID（world_categories.idを参照、NOT NULL） |
| category_id   | int           |      |      | カテゴリID（世界のカテゴリ自体の設定を記述する際に用いる。NULL可、用途に応じて利用） |
| title         | varchar(255)  | ○    |      | 設定タイトル                   |
| description   | text          |      |      | 設定の説明                     |
| delete_flg    | tinyint(1)    | ○    |      | 削除フラグ（0:有効, 1:削除済み） |
| created_at    | datetime      | ○    |      | 作成日時                       |
| updated_at    | datetime      | ○    |      | 更新日時                       |
| deleted_at    | datetime      |      |      | 削除日時                       |

---

## インデックス

| インデックス名           | 種類 | 説明               | カラム                |
|------------------------|------|-------------------|----------------------|
| PRIMARY KEY            | 主キー | 設定IDの主キー     | id                   |
| INDEX                  | 通常 | 世界カテゴリ検索用 | parent_id            |
| INDEX                  | 通常 | カテゴリ検索用     | category_id          |
| INDEX                  | 通常 | タイトル検索用     | title                |
| INDEX                  | 通常 | 削除フラグ検索用   | delete_flg           |
| INDEX                  | 通常 | 作成日時検索用     | created_at           |
| INDEX                  | 通常 | 更新日時検索用     | updated_at           |
| INDEX                  | 通常 | 削除日時検索用     | deleted_at           |
| FULLTEXT               | 全文検索 | タイトルの全文検索用 | title |
| UNIQUE                 | 複合一意 | 世界カテゴリID・タイトルの組み合わせ一意 | parent_id, title |

---

## 制約条件

### 主キー制約
- `id`: 自動採番（AUTO_INCREMENT）

### 外部キー制約
- `parent_id` → `world_categories.id`（NOT NULL）
- `category_id` → `world_categories.id`（NULL可）

### チェック制約
- `title`: 空文字列でないこと
- `delete_flg` IN (0, 1)
- `category_id`: NULL可（任意）

### 一意制約
- `parent_id`, `title`の組み合わせは一意

---

## 設計補足

### データ分離の目的
- **パフォーマンス向上**: 一覧表示時は`worlds`のみ取得
- **拡張性**: 内容情報の柔軟な追加が可能
- **権限管理**: 基本情報と内容情報で異なる権限設定

### 1対1の関係
- 各世界は必ず1つの設定情報を持つ
- 世界削除時は設定情報も削除
- 世界作成時は設定情報も同時作成

### 検索機能
- タイトルによる部分一致検索
- 全文検索によるタイトル検索
- カテゴリによる検索は`world_categories`テーブルで管理

### 多言語対応の準備
- 将来的に言語別テーブルへの拡張が可能
- 現在は日本語のみ対応

### 論理削除
- `delete_flg`で論理削除を実現
- `deleted_at`で削除日時を記録
- 削除された設定は通常の検索から除外

### `category_id`の説明
- `category_id`は、世界のカテゴリ自体の設定情報（例：カテゴリの説明や属性など）を記述する際に用いるカラムです。
- `category_id`が設定されている場合、`title`は必ず対応するカテゴリ名（categories.name）と一致しなければなりません。この制約はDBレベルでは実現できないため、サーバーサイド（アプリケーション側）でバリデーションを行ってください。

---

## 関連テーブル

- `worlds`: 1対1の関係（世界の基本情報）
- `world_categories`: 多対1の関係（世界カテゴリ関連）
- `setting_histories`: 1対多の関係（設定情報の変更履歴）
- `world_tags`: 1対多の関係（世界のタグ管理）

---

## 運用上の注意点

1. **データ整合性**: 世界作成時は必ず設定情報も作成
2. **検索最適化**: 全文検索インデックスの定期的な最適化
3. **パフォーマンス**: 一覧表示時はJOINを避ける
4. **バックアップ**: 設定情報の定期的なバックアップ
5. **監視**: 全文検索のパフォーマンス監視
6. **タグ管理**: タグによる検索は`world_tags`テーブルで一元管理
7. **論理削除**: 削除された設定の適切な処理
8. **削除日時管理**: 削除日時の正確な記録
