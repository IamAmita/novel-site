# 小説テーブル（novels）

---

## 概要
小説作品の基本情報を管理するテーブル。ユーザーが投稿した小説のタイトルや説明、公開状態などを保持する。

---

## テーブル定義

| 属性名        | 型            | 必須 | 一意 | 説明                           |
|---------------|---------------|------|------|--------------------------------|
| id            | int           | ○    | ○    | 小説ID（主キー）               |
| user_id       | int           | ○    |      | 投稿ユーザーID（users.idを参照、NOT NULL） |
| publish_flg   | tinyint(1)    | ○    |      | 公開フラグ（0:非公開, 1:公開） |
| delete_flg    | tinyint(1)    | ○    |      | 削除フラグ（0:有効, 1:削除済み） |
| created_at    | datetime      | ○    |      | 作成日時                       |
| updated_at    | datetime      | ○    |      | 更新日時                       |
| deleted_at    | datetime      |      |      | 削除日時                       |

---

## インデックス

| インデックス名           | 種類 | 説明               | カラム                |
|------------------------|------|-------------------|----------------------|
| PRIMARY KEY            | 主キー | 小説IDの主キー     | id                   |
| INDEX                  | 通常 | ユーザー検索用     | user_id              |
| INDEX                  | 通常 | 削除フラグ検索用   | delete_flg           |
| INDEX                  | 通常 | 作成日時検索用     | created_at           |
| INDEX                  | 通常 | 更新日時検索用     | updated_at           |
| INDEX                  | 通常 | 削除日時検索用     | deleted_at           |
| INDEX                  | 通常 | 公開フラグ検索用   | publish_flg          |
| FULLTEXT               | 全文検索 | タイトルの全文検索用 | title |
| UNIQUE                 | 複合一意 | ユーザーID・タイトルの組み合わせ一意 | user_id, title |

---

## 制約条件

### 主キー制約
- `id`: 自動採番（AUTO_INCREMENT）

### 外部キー制約
- `user_id` → `users.id`（NOT NULL）

### チェック制約
- `publish_flg` IN (0, 1)
- `delete_flg` IN (0, 1)

### 一意制約
- `user_id`, `title`の組み合わせは一意

---

## 設計補足

- **論理削除**: `delete_flg`で論理削除を実現し、`deleted_at`で削除日時を記録。
- **公開状態**: `publish_flg`で公開・非公開を管理。
- **検索機能**: タイトルによる部分一致・全文検索に対応。
- **拡張性**: 小説本文や章情報は別テーブルで管理することを想定。

---

## 関連テーブル

- `users`: 多対1の関係（投稿ユーザー）
- `novel_chapters`: 1対多の関係（小説の章情報）
- `novel_histories`: 1対多の関係（小説の変更履歴）
- `novel_tags`: 1対多の関係（小説のタグ管理）

---

## 運用上の注意点

1. **データ整合性**: 小説作成時は必ずユーザーIDを指定
2. **検索最適化**: 全文検索インデックスの定期的な最適化
3. **パフォーマンス**: 一覧表示時はJOINを避ける
4. **バックアップ**: 小説情報の定期的なバックアップ
5. **論理削除**: 削除された小説の適切な処理
6. **削除日時管理**: 削除日時の正確な記録
