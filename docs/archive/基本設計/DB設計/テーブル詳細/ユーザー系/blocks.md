# blocks テーブル詳細

---

## 概要
ユーザー間のブロック関係を管理するテーブルです。ブロックするユーザー、ブロックされるユーザー、ブロック日時、論理削除フラグなどを含みます。

---

## テーブル定義

| 属性名         | 型         | 必須 | 一意 | 説明                         |
|----------------|------------|------|------|------------------------------|
| id             | int        | ○    | ○    | ブロックID（主キー）         |
| blocker_id     | int        | ○    |      | ブロックするユーザーID       |
| blocked_id     | int        | ○    |      | ブロックされるユーザーID     |
| delete_flg     | tinyint    | ○    |      | 論理削除フラグ（0:有効, 1:削除済み） |
| created_at     | datetime   | ○    |      | ブロック日時                 |
| updated_at     | datetime   |      |      | 更新日時（解除・再ブロック時等）     |

---

## インデックス

| インデックス名 | 種類 | 説明 | カラム |
|----------------|------|------|--------|
| PRIMARY KEY | 主キー | ブロックIDの主キー | id |
| UNIQUE | 複合一意 | ブロック関係の一意制約 | blocker_id, blocked_id, delete_flg |
| INDEX | 通常 | ブロックするユーザー検索用 | blocker_id |
| INDEX | 通常 | ブロックされるユーザー検索用 | blocked_id |
| INDEX | 通常 | 論理削除フラグ検索用 | delete_flg |
| INDEX | 通常 | ブロック日時検索用 | created_at |

---

## 制約条件

### 主キー制約
- `id`: 自動採番（AUTO_INCREMENT）

### 一意制約
- `blocker_id, blocked_id, delete_flg`: ブロック関係は論理削除フラグを含めて一意である必要があります

### 外部キー制約
- `blocker_id` → `users.id`: ブロックするユーザーテーブルを参照
- `blocked_id` → `users.id`: ブロックされるユーザーテーブルを参照

### チェック制約
- `blocker_id` ≠ `blocked_id`: 自分をブロックすることはできません
- `delete_flg`: 0または1の値のみ許可（0:有効, 1:削除済み）

---

## 設計補足

### ブロックするユーザー（blocker_id）
- ブロックを実行するユーザー
- 存在するユーザーである必要があります

### ブロックされるユーザー（blocked_id）
- ブロックされるユーザー
- 存在するユーザーである必要があります

### 論理削除フラグ（delete_flg）
- 0:有効、1:削除済みとして管理
- ブロック解除時はdelete_flg=1に更新
- 履歴や監査のため物理削除は行わない

### ブロック日時（created_at）
- ブロック関係が成立した日時
- 履歴追跡のために記録

### 更新日時（updated_at）
- ブロック解除や再ブロック時に更新
- 履歴や監査のために利用

### ブロック効果
- ブロックされたユーザーの投稿は表示されない
- ダイレクトメッセージの送受信ができない
- フォロー関係が自動的に解除される

---

## 関連テーブル

- `users`: 多対1の関係（ブロックするユーザー）
- `users`: 多対1の関係（ブロックされるユーザー）

---

## 運用上の注意点

1. **自己ブロック**: 自分をブロックすることはできません
2. **重複ブロック**: 同じユーザーを複数回ブロックすることはできません（delete_flg=0のみ有効）
3. **ブロック解除**: delete_flg=1で論理削除、物理削除は行わない
4. **相互ブロック**: 相互ブロックは2つのレコードで管理
5. **updated_at**: ブロック解除や再ブロック時に更新
