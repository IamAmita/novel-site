# direct_messages テーブル詳細

---

## 概要
ユーザー間のダイレクトメッセージを管理するテーブルです。送信者、受信者、メッセージ本文、既読状態、論理削除フラグなどを含みます。

---

## テーブル定義

| 属性名              | 型         | 必須 | 一意 | 説明                                 |
|---------------------|------------|------|------|--------------------------------------|
| id                  | int        | ○    | ○    | メッセージID（主キー）               |
| sender_id           | int        | ○    |      | 送信者ユーザーID                     |
| receiver_id         | int        | ○    |      | 受信者ユーザーID                     |
| body                | text       | ○    |      | メッセージ本文                       |
| is_read             | tinyint    | ○    |      | 既読/未読フラグ（0:未読、1:既読）     |
| sender_delete_flg   | tinyint    | ○    |      | 送信者側論理削除フラグ（0:有効, 1:削除済み） |
| receiver_delete_flg | tinyint    | ○    |      | 受信者側論理削除フラグ（0:有効, 1:削除済み） |
| created_at          | datetime   | ○    |      | 送信日時                             |

---

---

## 制約条件

### 主キー制約
- `id`: 自動採番（AUTO_INCREMENT）

### 外部キー制約
- `sender_id` → `users.id`: 送信者ユーザーテーブルを参照
- `receiver_id` → `users.id`: 受信者ユーザーテーブルを参照

### チェック制約
- `sender_id` ≠ `receiver_id`: 自分にメッセージを送信することはできません
- `is_read`: 0または1の値のみ許可
- `sender_delete_flg`, `receiver_delete_flg`: 0または1の値のみ許可（0:有効, 1:削除済み）

---

## 設計補足

### 送信者（sender_id）
- メッセージを送信したユーザー
- 存在するユーザーである必要があります

### 受信者（receiver_id）
- メッセージを受信するユーザー
- 存在するユーザーである必要があります

### メッセージ本文（body）
- メッセージの内容
- テキスト形式で保存
- HTMLタグ等の特殊文字はエスケープ処理

### 既読/未読フラグ（is_read）
- `1`: 既読
- `0`: 未読
- 受信者がメッセージを開いた時に更新

### 論理削除フラグ（sender_delete_flg, receiver_delete_flg）
- 送信者・受信者ごとに論理削除フラグを持つ
- どちらか一方が削除しても、もう一方が有効ならメッセージは残る
- 両者が削除した場合のみ物理削除可能

## 関連テーブル

- `users`: 多対1の関係（送信者）
- `users`: 多対1の関係（受信者）

---

## 運用上の注意点

1. **自己送信**: 自分にメッセージを送信することはできません
2. **既読管理**: 受信者がメッセージを開いた時に既読フラグを更新
3. **削除管理**: 送信者・受信者それぞれが論理削除可能。両者削除時のみ物理削除
4. **プライバシー**: メッセージ内容の適切な管理
