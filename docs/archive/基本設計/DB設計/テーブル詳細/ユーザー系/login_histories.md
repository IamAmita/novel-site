# login_histories テーブル詳細

---

## 概要
ユーザーのログイン履歴を管理するテーブルです。ログイン日時、IPアドレス、端末情報、成功/失敗情報などを含みます。

---

## テーブル定義

| 属性名         | 型         | 必須 | 一意 | 説明                         |
|----------------|------------|------|------|------------------------------|
| id             | int        | ○    | ○    | ログイン履歴ID（主キー）      |
| user_id        | int        | ○    |      | ユーザーID（外部キー）       |
| login_at       | datetime   | ○    |      | ログイン日時                 |
| ip_address     | varchar    |      |      | IPアドレス                   |
| user_agent     | varchar    |      |      | 端末情報                     |
| success        | tinyint    | ○    |      | 成功/失敗フラグ（0:成功、1:失敗） |
| fail_reason_id | int        |      |      | 失敗理由ID（master_reasons参照） |

---

## インデックス

| インデックス名 | 種類 | 説明 | カラム |
|----------------|------|------|--------|
| PRIMARY KEY | 主キー | ログイン履歴IDの主キー | id |
| INDEX | 通常 | ユーザーID検索用 | user_id |
| INDEX | 通常 | ログイン日時検索用 | login_at |
| INDEX | 通常 | 成功/失敗検索用 | success |
| INDEX | 通常 | IPアドレス検索用 | ip_address |
| INDEX | 通常 | 失敗理由検索用 | fail_reason_id |

---

## 制約条件

### 主キー制約
- `id`: 自動採番（AUTO_INCREMENT）

### 外部キー制約
- `user_id` → `users.id`: ユーザーテーブルを参照
- `fail_reason_id` → `master_reasons.id`: 理由マスタを参照

### チェック制約
- `success`: 0または1の値のみ許可
- `ip_address`: IPv4またはIPv6形式である必要があります

---

## 設計補足

### ログイン日時（login_at）
- ログイン試行の日時を記録
- 成功・失敗に関わらず記録

### IPアドレス（ip_address）
- ログイン試行元のIPアドレス
- セキュリティ監視に使用
- IPv4、IPv6両方に対応

### 端末情報（user_agent）
- ブラウザやアプリの情報
- 不正アクセス検知に使用

### 成功/失敗フラグ（success）
- `0`: ログイン成功
- `1`: ログイン失敗

### 失敗理由ID（fail_reason_id）
- master_reasonsテーブルで管理
- 例：1=パスワード誤り、2=アカウント無効、3=2FA失敗など
- 失敗理由の集計や多言語対応が容易

---

## 関連テーブル

- `users`: 多対1の関係（ユーザー基本情報）
- `master_reasons`: 多対1の関係（失敗理由マスタ）

---

## 運用上の注意点

1. **データ量**: 定期的なアーカイブ・削除が必要
2. **セキュリティ**: 不正アクセス検知に活用
3. **プライバシー**: 個人情報の適切な管理
4. **パフォーマンス**: インデックスの最適化

- セキュリティ監査に活用
- セキュリティ監査や集計時にfail_reason_idで分類可能
