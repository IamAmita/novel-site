# 機能範囲定義

**目的**: 全実装で提供すべき機能の明確な範囲定義  
**対象**: 技術に依存しない機能要件の境界線  
**位置づけ**: 創作者を主眼に置いたプラットフォームの機能スコープ

**参照（正本）**:

- [プロダクト定義](../project/プロダクト定義.md)
- [Phase1-確定メモ](../project/Phase1-確定メモ.md)

**用語**: 世界観 / 設定 / 作品（本ドキュメント内で統一）

**チェックボックス**: `[x]` = 要件確定済み / `[ ]` = 未確定または将来 Phase

---

## ドメイン構造

全 Phase 共通の概念モデル。

```
作者
└── ペンネーム
    └── 世界観（World）
        ├── 設定（Setting）
        └── 作品
            └── 章 → 話（本文）
```

## 実装フェーズ計画

### Phase 1: 設定管理と執筆

**目的**: 設定管理を自由かつ詳細に行い、それを見ながら執筆できる状態を実現する

#### 最小機能セット

- ユーザー登録・ログイン・ペンネーム
- 世界観・設定管理（テンプレート、カスタムフィールド、関係性、検索）
- 執筆画面からの設定参照
- 作品執筆（章・話・表紙・変更履歴）
- 自分向け閲覧・一覧・ソート
- 設定・作品・本文の検索

#### 成功基準

- [ ] 設定管理が自由かつ詳細にできる
- [ ] 設定を執筆画面から参照できる
- [ ] 設定を見ながら執筆できる

#### 任意（Phase 1）

- 世界観の検索
- 設定間関係の視覚化
- 縦書き・横書き切替
- ルビ（入力・表示）
- タグ・カテゴリ

---

### Phase 2: 共同制作と限定公開

**目的**: 共同制作者と協働し、限定公開・フィードバックを行える状態を実現する

#### 追加機能

- 共同制作（最優先）
- 共同制作者向け閲覧
- 限定公開・設定の公開範囲制御
- 公開前評価システム
- コミュニケーション（コメント、フォロー、DM、掲示板）

#### 成功基準

- [ ] 共同制作が機能する

#### 任意（Phase 2）

- 作者・ユーザー検索
- タグ・ジャンル絞り込み
- 全文検索・あいまい検索

---

### Phase 3: 一般公開と読者向け機能

**目的**: 作品公開・閲覧機能を提供し、読者向け体験を段階的に拡張する

#### 追加機能

- 一般向け公開・閲覧
- お気に入り・ブックマーク
- 関連作品・おすすめ・ランキング
- 通知
- 管理者機能（3 以降）

#### 成功基準

- [ ] 一般向け閲覧が可能

#### 任意（Phase 3 以降）

- 分析・レポート（閲覧数統計等）

---

## 対象外機能（Out of Scope）

### 明確に対象外

- **課金・決済・広告**
- **動画・音声コンテンツ**
- **ゲーム機能**
- **商業出版支援**
- **多言語対応**（日本語のみ）
- **モバイルアプリ**（Web のみ）
- **大規模スケール**（数千人同時接続等）
- **SNS 連携・外部 API 公開・電子書籍エクスポート**
- **2 段階認証・ログイン履歴**

### 将来検討

- **不適切コンテンツ対応**（通報・モデレーション）
- **オフライン機能**
- **エンタープライズ機能**

## 提供方針

Python/Django 実装として、上記スコープを満たすプロダクトを開発する。

- API・DB・Docker の具体設計は実装側が独自管理
- ドメイン概念は [docs/domain/](../domain/) を参照
- スコープ変更時は本ドキュメントと [プロダクト定義](../project/プロダクト定義.md) の整合を確認

---

**管理ルール**: 機能追加時は必ずスコープ範囲と Phase を確認  
**変更プロセス**: スコープ変更は実装への影響を評価してから決定  
**品質基準**: Phase 1（設定管理・執筆）の品質を最優先。任意機能の実装にコア機能を犠牲にしない
