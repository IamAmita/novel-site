# 画面仕様書レビュー残課題

**作成日**: 2026-09-03
**方針**: 2026-09-03のレビュー指摘は一旦保留し、実装を進めながら気になったものから順次対応・仕様書反映する（ユーザー決定）。対応したら本ファイルからチェックを付け、該当仕様書・ドメイン設計を更新する。

各項目の「対応案」は返答時に提示した推奨方針。実装時に改めて判断してよい。

## 重要

- [ ] 1. `[[Setting名]]`参照の一意性（重大）— 対応案: 保存形式を `[[名前|sID]]` の名前＋IDハイブリッド記法にし、リンク解決はID。エディタ表示は現在名。手入力は保存時に解決（一意なら自動、複数なら選択UI）
- [ ] 2. 連鎖削除後の復元範囲（重大）— 対応案: 論理削除時に削除バッチID（UUID）を連鎖対象全レコードへ付与し、復元は同一バッチのみ連鎖復元。ドメイン設計（World/Novel/Setting/User.md）への遡り追記が必要
- [ ] 3. Chapter削除と復元の矛盾（重大）— 対応案: **復元時も章は空**（話は引き戻さない）。DL-03・SC-16に明記
- [ ] 4. 親Settingの循環参照防止（重大）— 対応案: 親候補から自分＋全子孫を除外＋サーバー側循環チェック。所属作品変更の制約（狭化は全子孫が同一作品時のみ可、拡大は親が作品専用なら不可）も定義
- [ ] 5. ChangeLogのSettingFieldキー衝突（高）— 対応案: 内部キーを`fields.<field_id>`にし、当時の項目名を`changes`内に保存。Novel.mdのChangeLog仕様の修正が必要
- [ ] 6. 認証情報の回復手段（高）— 対応案: パスワード欄に表示切替を追加／SC-05でemail編集可に変更／回復手順として`manage.py changepassword`を運用手順に明記
