# データベース設計

## 設計方針

### 基本コンセプト
PostgreSQL によるリレーショナル設計で、World（世界観）・Setting（設定）・作品（章・話）を中心としたデータモデルを構築する。

### データベース選定理由
- **技術適合性**: Django ORM との親和性
- **実用性**: 実際の開発現場での採用実績
- **拡張性**: JSONB・全文検索等、柔軟な拡張機能

## 共通データモデル

### 核心エンティティ
- **Users**: ユーザー情報・プロフィール・認証
- **World**: 世界観（作品・設定の上位概念）
- **Setting**: 設定（キャラクター・世界・物品・概念等）
- **Novels**: 小説作品・メタデータ
- **Chapters / Episodes**: 章・話・本文

### データ関係性
- **階層構造**: World → Setting、World → Novel → Chapter → Episode
- **所有関係**: User → World
- **関係定義**: Setting 間の関係性（「A の師匠は B」等）

詳細は [shared/domain/core-entities.md](../../shared/domain/core-entities.md)、実装固有のスキーマは [implementations/python-django/docs/設計書/02_DB設計.md](../../implementations/python-django/docs/設計書/02_DB設計.md) を参照。

## 採用データベース

- **PostgreSQL 15**: メインデータベース（ACID準拠・正規化設計・複雑クエリ）
- **Redis**: セッション・キャッシュ・一時データ

## スキーマ管理

### バージョン管理
- **マイグレーション**: Django マイグレーションによる段階的適用
- **互換性**: 後方互換性の保証

### 変更管理
- **影響分析**: スキーマ変更の影響範囲分析
- **テスト**: スキーマ変更後の動作確認

## 性能設計

### 最適化指針
- **読み取り最適化**: インデックス設計、select_related / prefetch_related の活用
- **書き込み最適化**: 効率的なデータ更新
- **キャッシュ**: Redis によるクエリ結果キャッシュ

## 運用考慮事項

### バックアップ戦略
- **定期バックアップ**: PostgreSQL の自動バックアップ
- **ポイントインタイム**: 特定時点への復旧

### 監視・アラート
- **ヘルスチェック**: DB稼働状況監視
- **性能監視**: レスポンス時間・スループット
