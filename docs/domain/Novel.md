## データモデル

### Novel（作品）

| フィールド | 型・制約 |
|---|---|
| world | 所属World（外部キー、必須） |
| title | 文字列、必須 |
| synopsis | 文字列（TextField）、任意（あらすじ） |
| cover_image | 画像、任意（未設定時は共通デフォルト画像を表示） |
| status | 選択肢: `writing`（執筆中）/ `reviewing`（レビュー中）/ `completed`（完成） |
| visibility | 選択肢: `private`（非公開）/ `limited`（限定公開）/ `public`（一般公開）。詳細は[Publishing.md](Publishing.md)参照 |
| category | 所属Category（外部キー、任意）。詳細は[Reader.md](Reader.md)参照 |
| created_at / updated_at | タイムスタンプ |
| deleted_at | 論理削除用（NULLなら有効） |
| deleted_by | 削除実行者（外部キー、User参照、任意）。管理者による強制削除の判定に使う。詳細は[Moderation.md](Moderation.md)参照 |

#### 決定事項

- 名義（owner_pen_name）: **持たない**（2026-08-22決定）。作品の名義は常に所属Worldの`owner_pen_name`を参照する（Novel独自の名義選択は行わない。シンプルさを優先）
- 表紙画像: World.mdと同様、**任意・未設定時は共通デフォルト画像**
- 削除時の配下データ（Chapter・Episode）: **連鎖的に論理削除**（World.mdと同様の方針）
- 名前重複: **許容**（World.mdと同様、同一World内でも同名作品を複数作成できる）
- 進捗ステータス: **執筆中／レビュー中／完成**の3段階（2026-08-22決定、詳細は[Collaboration.md](Collaboration.md)参照）。作成時は`writing`がデフォルト
- 公開範囲: **非公開／限定公開／一般公開**の3段階（2026-08-22決定、判定ロジック・個別指定の詳細は[Publishing.md](Publishing.md)参照）。作成時は`private`がデフォルト

### Chapter（章）

| フィールド | 型・制約 |
|---|---|
| novel | 所属Novel（外部キー、必須） |
| title | 文字列、必須 |
| order | 表示順（整数） |
| created_at / updated_at | タイムスタンプ |
| deleted_at | 論理削除用（NULLなら有効） |

#### 決定事項

- 章: **任意**（functional-scope.md E参照）。作品によっては章を作らず、話（Episode）だけで構成できる
- 並び順: **order整数フィールドで手動並び替え**（2026-08-22決定）。ドラッグ操作等で並び替えたのち、order値を採番し直す

### Episode（話）

| フィールド | 型・制約 |
|---|---|
| novel | 所属Novel（外部キー、必須） |
| chapter | 所属Chapter（外部キー、**任意**）。NULLなら章に属さずNovel直下 |
| title | 文字列、必須 |
| body | 文字列（TextField）、任意 |
| order | 表示順（整数） |
| visibility | 選択肢: `NULL`（Novelを継承）/ `private` / `limited` / `public`。詳細は[Publishing.md](Publishing.md)参照 |
| view_count | 整数、デフォルト0。詳細は[Reader.md](Reader.md)参照 |
| created_at / updated_at | タイムスタンプ |
| deleted_at | 論理削除用（NULLなら有効） |
| deleted_by | 削除実行者（外部キー、User参照、任意）。管理者による強制削除の判定に使う。詳細は[Moderation.md](Moderation.md)参照 |

#### 決定事項

- 章との関係: `chapter`が**NULLの場合はNovel直下の話**として扱う（章あり作品・章なし作品を同一モデルで表現できる）
- 本文の文字数制限: **なし**（2026-08-22決定）。個人利用前提でパフォーマンス要件を設けない方針（functional-scope.md G参照）と一貫させる
- 並び順: Chapterと同様、**order整数フィールドで手動並び替え**。章に属する話は章内で、章に属さない話はNovel直下で独立して並び順を持つ
- 公開範囲: **未設定（NULL）ならNovelの設定を継承**（2026-08-22決定）。値を設定すればNovelの公開範囲を話単位で上書きできる（詳細は[Publishing.md](Publishing.md)参照）

### ChangeLog（変更履歴）

#### 設計思想（2026-08-22決定）

この機能の核心は「Gitやバージョン管理を知らなくても、作者・編集者（共同制作者）が『何がどう変わったか』を具体的な差分として直感的に確認できる体験」を提供すること。GitHubのdiff表示が持つ価値——変更点が一目で分かること——は優れているが、多くの執筆者はその体験をしたことがない。コミットメッセージ・ブランチ・マージといったGit特有の複雑な概念は持ち込まず、**保存するたびに自動で差分が記録され、あとから振り返れる**というシンプルな体験に留める。対象読者はあくまで作者・編集者（共同制作者）であり、読者に見せる機能ではない（閲覧権限は下記参照）。

| フィールド | 型・制約 |
|---|---|
| target_type | 選択肢: `world` / `novel` / `chapter` / `episode` / `setting` |
| target_id | 対象オブジェクトのid（整数） |
| user | 変更者（外部キー、User参照） |
| action | 選択肢: `create` / `update` / `delete` |
| changes | JSON、任意。変更されたフィールドごとに`{フィールド名: {before: 変更前の値, after: 変更後の値}}`を記録する。`create`は各フィールドの`after`のみ、`delete`は`before`のみ（またはNULL） |
| created_at | タイムスタンプ |

#### 決定事項

- 実装方式: **汎用ChangeLogモデル**（2026-08-22決定）。`target_type`＋`target_id`で対象を特定する単一テーブルに、World/Novel/Chapter/Episode/Settingすべての変更実績を集約する
- 記録粒度（2026-08-22決定、方針変更）: **変更前後の値をフィールド単位で保存**し、GitHubのコミット履歴のような差分（diff）表示を実現する。対象は`target_type`の各モデルの**主要フィールド全て**（例: World.description、Novel.synopsis、Episode.bodyなど）で、統一的に扱う。誰が・いつ・何を変更したかに加え、何がどう変わったかまで追える
- 記録タイミング: 対象オブジェクトの作成・更新・削除（論理削除）のたびに1レコード追加する
- SettingFieldの扱い（2026-08-22決定）: 独立した`target_type`は作らず、**`target_type=setting`のChangeLogに統合**する。SettingField（Settingのカスタム項目）の追加・変更・削除は、`changes`の中に`fields.<項目名>: {before, after}`という形で記録し、Setting本体の変更（name／description等）と合わせて「1つのSettingの変更履歴」として一体で確認できるようにする
- PenNameの扱い（2026-08-22決定）: ChangeLogの対象に**含めない**。表示名・bio等の変更は記録しない（`target_type`に`pen_name`は追加しない）
- 閲覧権限（2026-08-22決定）: **常に作者・共同制作者（`status=accepted`のCollaborator）限定**。対象のNovel／World／Setting自体が一般公開（`public`）されていても、その変更履歴（diff）は読者には見せない。上記の設計思想（作者・編集者向けの体験）に基づく
- 除名済み共同制作者の変更者表示（2026-08-22決定）: Comment・BoardPostとは異なり**匿名化しない**。ChangeLogは「誰が何を変更したか」を追跡する記録目的のため、除名後も変更者は実名（当時のUser・PenName等）のまま表示する

## 画面仕様

### 作品一覧画面

- F（閲覧・検索）で定義した「作品一覧」メニューに対応。World横断で自分の作品を一覧できる
- 表示形式: **リスト形式**（World一覧画面にならう）
- 検索: タイトル・本文の部分一致検索
- デフォルトソート順: 更新日時の新しい順（World一覧にならう）

### 作品詳細画面

- 表示内容: タイトル・あらすじ・表紙画像・所属World（名義表示）・章一覧（章がある場合）・話一覧（章に属さないものを含む）
- 変更履歴（ChangeLog）を確認する導線をここに設置する

### 作品作成・編集フォーム

- 入力項目: 所属World（必須、作成時のみ指定・変更不可）、タイトル（必須）、あらすじ（任意）、表紙画像（任意）
- 名義（ペンネーム）は所属Worldの`owner_pen_name`を表示するのみで、フォーム上での選択は行わない

### 作品削除

- 論理削除。配下のChapter・Episodeは連鎖削除
- 削除確認: 単純な確認ダイアログ（World.mdの方針にならう）
- 削除後の復元: World.mdと同じ方針。期限なく手動復元可能
- 復元UI（2026-08-22決定）: **階層ごとに同じフィルタ方式**を採用する。作品一覧画面に「削除済みを表示」トグルを設け、そこから削除済みNovelを復元できる（World.md・Setting.mdと同じ体験）。Chapter・Episodeは、所属する作品の**作品詳細画面**内に同様の「削除済みを表示」トグルを設け、そこから復元する
- 復元対象の制限（2026-08-22決定）: `deleted_by`が管理者による削除の場合は、この復元UIの対象外とする（Episodeも同様。詳細は[Moderation.md](Moderation.md)参照）

### 章（Chapter）管理

- 作品詳細画面から、章の追加・編集（タイトル変更）・削除・並び替えができる
- 削除は論理削除。**配下のEpisodeは連鎖削除せず、Novel直下の話（chapter=NULL）へ自動的に付け替える**（2026-08-22決定）。執筆内容を守ることを優先し、章の削除で話が失われることはない

### 話（Episode）執筆画面

- タイトル・本文を編集する
- 設定参照: 本文中にリンク記法（例: `[[Setting名]]`）で参照を埋め込めるほか、サイドパネルからSettingを選んで挿入することもできる
- 保存のたびにChangeLogへ記録される
- 閲覧権限がない参照先の表示制御（2026-08-22決定）: 読者がリンク先Settingの閲覧権限を持たない場合、**[Setting.md](Setting.md)のSettingFieldと同じルール**を適用する。リンクテキスト（Setting名）は表示するが、無効化して遷移も詳細表示もさせない（執筆者本人の本文自体は変更しない）

### 変更履歴（ChangeLog）閲覧画面

- 対象（World/Novel/Chapter/Episode/Setting）ごとに、誰がいつ何を変更したかのログを一覧できる
- 各対象の詳細画面から、その対象に関する変更履歴に絞って確認できる導線を用意する
- 閲覧権限（2026-08-22決定）: 作者・共同制作者（`status=accepted`のCollaborator）にのみ導線・画面を表示する。対象が一般公開されていても、読者には見せない
- 範囲（2026-08-22決定）: **対象ごとの絞り込み表示のみ**とする。World全体の変更履歴を横断的にまとめて見れるページは今回は作らない（必要になれば別途追加を検討する）
- 一覧の見た目（2026-08-22決定）: GitHubのコミット履歴のように、**誰が・いつ・何を（create/update/delete）**を時系列でリスト表示する
- 差分表示（2026-08-22決定）: 一覧の各行から展開すると、`changes`に記録されたフィールドごとの変更前後を**diff形式（変更前を打ち消し線・削除色、変更後を追加色で表示する等）**で確認できる。複数フィールドが変わった場合は、フィールドごとに差分を並べる
- 過去バージョンへの復元（revert）機能（2026-08-22決定）: **今回は見送る**。設計思想の中心は「差分を確認できる体験」であり、ワンクリックで過去の内容に戻す機能は範囲に含めない。必要になれば別途追加を検討する
