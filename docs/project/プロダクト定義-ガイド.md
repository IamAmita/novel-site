## 1. プロダクト定義とは

**プロダクト定義**は、「このサイトは何のために存在し、誰に何を提供するか」を技術に依存しない言葉で書いた文書です。

### プロジェクト概要との違い

| 観点 | プロジェクト概要（`概要.md`） | プロダクト定義（本ガイドの成果物） |
|------|-------------------------------|-----------------------------------|
| 主語 | 開発者・学習者 | サイトの利用者（読者・作者） |
| 焦点 | 5言語実装、技術比較、学習目標 | 提供する価値、機能の境界、成功の定義 |
| 読者 | 開発者自身 | 開発者 + 将来の要件整理の起点 |
| 変更頻度 | 低い | 要件整理のたびに見直す |

> **注意**: 本プロジェクトは「学習プロジェクト」でもあり「小説投稿サイト」でもあります。プロダクト定義では **利用者視点のプロダクト** を書き、学習目的は「開発の制約・背景」として短く触れる程度に留めます。

### 要件整理における位置づけ

```
プロダクト定義.md
    ↓ 具体化
Phase 1 確定メモ / functional-scope.md
    ↓ 展開
user-stories.md → business-rules.md → core-entities.md
```

## 2. 決め方（推奨手順）

### Step 1: 質問に答える（本ファイル §4 を使用）

各セクションの質問に **短い箇条書き** で答える。完璧な文章は不要。  
1セクション 15〜30 分を目安に、全部で 2〜3 時間。

### Step 2: 矛盾を洗い出す

記入後、次を確認する。

- 「最初に作るもの」と「将来作るもの」が混ざっていないか
- 「誰のため」に書いた機能と「提供価値」が一致しているか
- 「作らないもの」に書いた機能が、どこかに紛れ込んでいないか

### Step 3: ひな形（§3）に転記する

質問への回答を、§3 のテンプレート各項目に移す。  
1段落は **3〜5 文以内** を目安に簡潔に書く。

### Step 4: 1人でレビューする

翌日、もう一度読んで次の3点だけチェックする。

1. **初見の人が「何のサイトか」理解できるか**
2. **Phase 1 の境界が言えるか**（プロダクト定義段階では概要レベルでよい）
3. **「作らないもの」が明確か**

### Step 5: `プロダクト定義.md` として保存

`docs/project/プロダクト定義.md` に確定版を保存する。  
以降の要件整理（Phase 1 確定、`functional-scope.md` 更新）は本ファイルを正本として進める。

## 5. 記入時のルール

1. **技術用語を書かない** — Python、PostgreSQL、API などはプロダクト定義に含めない
2. **機能の羅列を避ける** — 「何ができるか」より「誰に何の価値があるか」
3. **Phase 1 の詳細設計は書かない** — 境界の概要まで。詳細は `functional-scope.md` へ
4. **1ファイル1目的** — 学習目的の長文は `概要.md` に任せ、ここでは短く
5. **未決定を隠さない** — §9 に書くことで後工程がスムーズになる
