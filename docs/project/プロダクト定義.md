# プロダクト定義

**バージョン**: 1.0  
**作成日**: 2026年5月25日

**根拠**: [プロダクト定義-ガイド.md](./プロダクト定義-ガイド.md) の質問への回答

## 1. 一言で言うと

創作者向けの設定管理サイト。共同制作を気軽に行うための場。

---

## 2. 背景と目的

### 2.1 なぜ作るのか

既存の小説投稿サイトは設定管理を十分に考慮しておらず、創作者が満足できる設定管理の利便性・機能性を持つサイトが見つからなかった。

本プロダクトは「なくては困る」というより、「あれば創作がより良くなる」という観点で、次の価値を提供する。

1. **詳細かつ分かりやすい設定管理** — 自由度が高く、詳細に、かつ簡便に設定を管理できる
2. **手軽な共同制作** — 共同制作者の募集・参加、簡便な進捗管理

### 2.2 開発の背景（制約）

- **個人開発**: 運営・開発は基本1名。管理者も最初は本人のみ
- **小規模想定**: 大規模コミュニティ（数千人規模）は想定しない。初期の想定ユーザーは自分自身
- **スケーリング**: 個人開発における主要な制約要因。詳細は今後検討
- **学習プロジェクトとの関係**: プロダクトの方向性とは切り離す。まずプロダクトを形にし、学習は後から考える

---

## 3. 対象ユーザー

### 3.1 主要ユーザー

| ユーザー種別 | 誰か | 主なニーズ |
|-------------|------|-----------|
| 作者（創作者） | 経験のある創作者 | 緻密な設定管理、共同制作の募集・参加 |
| 管理者 | 運営者本人（必要に応じて追加） | サイト運営、問い合わせ対応 |

**読者は想定しない。** ターゲットは創作者のみ。

### 3.2 想定しないユーザー・規模

| 項目 | 方針 |
|------|------|
| 一般読者 | ターゲット外（Phase 3 で一般向け閲覧を検討するが、読者獲得は目的としない） |
| 大規模コミュニティ | 想定しない |
| 明確な対象外ユーザー | 現時点では未定 |

### 3.3 商用利用の位置づけ

個人創作・アマチュア向けに特化する。プロダクトの質や評判次第で商用利用が広がればよいが、あくまで個人・アマチュア向けプロダクトの結果としての副次効果と捉える。

---

## 4. 提供価値（差別化）

### 4.1 作者にとっての価値

1. **設定管理の緻密さ** — 自由度が高く、詳細に、簡便に設定を管理できる
2. **共同制作募集の簡便さ** — 共同制作者の募集・参加が手軽にできる
3. **創作支援** — 設定管理・共同制作・公開前レビューを通じて、より良い作品ができる

### 4.2 読者にとっての価値

なし。読者向けのアピールは意図的に行わない。

### 4.3 既存サービスとの違い

| 観点 | 一般的な小説投稿サイト | 本プロダクト |
|------|----------------------|-------------|
| 主眼 | 作品の投稿・読者獲得 | 設定管理・共同制作 |
| 設定管理 | 考慮が薄い | コア機能 |
| 読者向け機能 | 充実 | 意図的に後回し（Phase 3） |
| 作品公開 | 主目的 | 副産物（他サイトへの投稿でも可） |

### 4.4 価値の優先順位

1. **設定管理**（主眼）
2. **共同創作**（コア価値だが、設定管理に次ぐ）
3. **作品公開**（副産物）

---

## 5. コア体験

### 5.1 作者が「よかった」と感じる瞬間

- 設定管理が満足にできる
- 共同制作や公開前の評価システムのおかげで、良い作品ができた

### 5.2 典型的な利用シーン

- **設定管理** — 作品の設定を整理・管理する
- **共同制作** — 共同制作者の募集や参加

### 5.3 サイトのトーン

**カジュアル**（創作支援ツールとしての親しみやすさ）。厳格さとのバランスは今後検討。

### 5.4 作品公開の位置づけ

最初は必須ではない。一般向け公開は Phase 3。他サイトへの投稿を主とする使い方も許容する。

---

## 6. 機能の境界

### 6.1 Phase 1 — 最初に形にするもの

| 機能 | 内容 |
|------|------|
| 設定管理 | 自由度が高く詳細な設定の作成・編集・管理（World を Setting の上位概念として含む） |
| 小説本文の執筆・投稿 | 作品本文の作成・編集 |
| 章・話の構成管理 | 作品の階層構造（章・話）の管理 |
| 自分向け閲覧 | 作者本人が作品を閲覧する |
| 縦書き・ルビ表示 | 読書体験（作者自身の確認用） |
| ユーザー管理 | 登録即作者 |

### 6.2 Phase 2 — コア価値の拡張

| 機能 | 内容 |
|------|------|
| 共同創作 | 招待・権限・進捗管理 |
| 共同制作者向け閲覧 | 共同制作者が作品を閲覧する |
| 公開前評価システム | 共同制作者同士のレビュー、創作者同士のベータレビュー |
| コメント・評価 | 作品・話へのフィードバック |
| フォロー・通知 | 更新通知等 |
| 掲示板 | 作品に紐づくスレッド |

### 6.3 Phase 3 — 一般向け

| 機能 | 内容 |
|------|------|
| 一般向け公開・閲覧 | 不特定の創作者以外が作品を閲覧する |

### 6.4 機能ごとに判断（検索等）

検索機能は、対象（設定・作品・ユーザー等）ごとに Phase 1 / 2 / 不要を個別に判断する。

### 6.5 対象外（作らないもの）

- 課金・有料会員・広告
- モバイルアプリ（Web のみ）
- 多言語対応（日本語のみ）
- 読者向け機能の積極的な充実
- 不適切コンテンツ対応（最初は不要）

---

## 7. 品質・運用の方針

### 7.1 品質の優先順位

**自由度** を最も譲れない。創作者が設定や作品を自由に管理できることが最優先。

納期より **品質** を優先する。

### 7.2 規模・パフォーマンスの想定

| 項目 | 想定 |
|------|------|
| 初期ユーザー | 自分自身 |
| 同時接続 | 個人利用規模 |
| 大規模スケール | 想定しない |

### 7.3 運用体制

| 項目 | 方針 |
|------|------|
| 運営者 | 本人1名（必要に応じて管理者追加） |
| SLA | 要検討（個人運用で現実的な水準を後日定義） |
| ユーザーサポート | サイト内の目安箱（問い合わせ・要望受付） |
| 不適切コンテンツ | 最初は対応機能なし |

## 8. 成功の定義

### 8.1 6ヶ月後の成功状態

**自分が使って満足できていること。**

### 8.2 作者視点の成功

**設定管理が快適にできること。**

### 8.3 開発者視点の成功

作者視点の成功と同じ。自分が日常的に使いたくなるツールになっていること。

### 8.4 数値目標

設けない。

### 8.5 公開前評価システム（Phase 2）

共同制作者同士のレビュー、創作者同士のベータレビュー。作品を一般公開する前に、信頼できる創作者からフィードバックを得る仕組み。

## 10. 既存ドキュメントとの主な差分

本プロダクト定義確定に伴い、以下の既存ドキュメントとの整合が必要。

| 既存の前提 | 本定義での変更 |
|-----------|---------------|
| 読者・作者・管理者の3者モデル | **読者はターゲット外** |
| 小説投稿サイトとしての読者体験 | 読者向け機能は Phase 3、積極的アピールなし |
| 作品公開が主目的 | **副産物**（他サイト投稿可） |
| 共同創作が Phase 2〜3 | Phase 2（コア価値だが設定管理の次） |
| `user-stories.md` の読者ストーリー | 見直し・削除または Phase 3 へ移動が必要 |
