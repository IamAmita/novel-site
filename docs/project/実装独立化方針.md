# 実装独立化方針

**更新日**: 2025年1月  
**目的**: implementationsフォルダの各サービスを完全に独立させる

---

## 🎯 基本方針

### 完全独立実装
各言語実装（implementations/）は独立したWebサービスとして動作し、他の実装に一切依存しない。

### 独立性の5原則

#### 1. 環境独立
- 各実装は独自のDocker Compose環境を持つ
- 必要なサービス（DB、Redis等）をすべて含む
- 他実装のサービスに依存しない

#### 2. 技術独立  
- 各実装が最適な技術スタックを自由選択
- データベースも実装ごとに最適化（PostgreSQL、MySQL、MongoDB等）
- フロントエンド技術も実装の特性に合わせて選択

#### 3. 開発独立
- 一つの実装のみで完結する開発体験
- 他実装の知識なしで開発・運用可能
- 独立したドキュメント・README

#### 4. デプロイ独立
- 各実装を個別にデプロイ可能
- 他実装のデプロイ状況に影響されない
- 独立した CI/CD パイプライン

#### 5. データ独立
- 各実装が独自のデータベースを持つ
- データ移行・同期は不要
- スキーマ設計も実装ごとに最適化

## 🐳 Docker設定の分離

### 旧方式（共通依存）
```bash
# Step 1: 共通サービス起動
cd shared/docker
docker-compose up -d postgres redis

# Step 2: 各実装起動
cd implementations/python-django/
python manage.py runserver  # 外部DBに接続
```

### 新方式（完全独立）
```bash
# 各実装で完結
cd implementations/python-django/
docker-compose up -d  # DB、Redis、アプリケーションすべて起動
```

### 各実装のDocker構成例

#### Python/Django実装
```yaml
# implementations/python-django/docker-compose.yml
services:
  web:
    build: .
    ports: ["8000:8000"]
    depends_on: [db, redis]
  
  db:
    image: postgres:15
    environment:
      POSTGRES_DB: django_novels
  
  redis:
    image: redis:7-alpine
```

#### TypeScript/Next.js実装
```yaml
# implementations/typescript-nextjs/docker-compose.yml
services:
  web:
    build: .
    ports: ["3000:3000"]
    depends_on: [db, redis]
  
  db:
    image: postgres:15
    environment:
      POSTGRES_DB: nextjs_novels
  
  redis:
    image: redis:7-alpine
```

#### PHP/Laravel実装
```yaml
# implementations/php-laravel/docker-compose.yml
services:
  web:
    build: .
    ports: ["80:80"]
    depends_on: [db, redis]
  
  db:
    image: mysql:8.0  # 実装最適化でMySQLを選択
    environment:
      MYSQL_DATABASE: laravel_novels
  
  redis:
    image: redis:7-alpine
```

## 🔗 共通要素の管理

### ✅ **真に共通なもの（不変）**

#### ビジネス要件・機能要件
- `shared/business/`で「何を作るか」を管理
- ユーザーストーリー・ビジネスルール・機能範囲
- 各実装で実現すべき機能の仕様

#### ドメイン概念・エンティティ関係
- `shared/domain/`でコアエンティティ概念を管理
- ユーザー・小説・設定の関係性定義
- ビジネス制約・ドメインルールの共有

#### UI/UXコンセプト・デザイン原則
- `shared/design/`でユーザー体験コンセプトを管理
- 画面コンセプト・デザイン原則・アクセシビリティ要件
- 各実装のフレームワーク特性を活かしたUI実装指針

#### 共通アセット
- `shared/assets/`で画像・アイコン・法的文書
- 各実装から相対パスで参照可能
- 著作権・ライセンスに注意して管理

### ❌ **技術依存で各実装が独自管理するもの**

#### API設計・実装
- **エンドポイント構造**: 各実装の技術特性に最適化
- **レスポンス形式**: 言語・フレームワークの慣例に従う
- **認証・認可方式**: 技術スタックに応じた実装
- **エラーハンドリング**: 各言語の例外処理に最適化

#### データベース設計・スキーマ
- **スキーマ構造**: DBの種類（RDBMS、NoSQL、等）に最適化
- **データ型選択**: 各DBの特性を活かした型定義
- **インデックス戦略**: パフォーマンス要件に応じて最適化
- **制約・バリデーション**: 各DBの機能を最大活用

#### アーキテクチャ・実装方式
- **アプリケーション構造**: 言語・フレームワークのベストプラクティス
- **モジュール分割**: 各技術スタックの設計思想に従う
- **設定管理**: 各実装の運用要件に最適化
