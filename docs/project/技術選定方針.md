# 技術選定方針

## 選定基準

### 学習価値
- **市場需要**: 転職・案件獲得での有用性
- **将来性**: 技術の成長性・継続性
- **学習効果**: 他技術への応用可能性

### 実装難易度
- **学習コスト**: 習得にかかる時間・労力
- **ドキュメント**: 日本語・英語での情報充実度
- **コミュニティ**: 質問・解決できる環境
- **開発体験**: ツール・エコシステムの充実

## 言語選定理由

### Python（バックエンド）
- **選定理由**: 最も学習しやすく汎用性が高い
- **期待効果**: Web開発基礎・Django設計思想の理解
- **市場価値**: AI・データサイエンス分野での需要

### TypeScript（フロントエンド）
- **選定理由**: 型安全なフロントエンド開発体験
- **期待効果**: React + TypeScript による SPA 開発
- **市場価値**: フロントエンド開発での高需要

## データベース選定

### 選定結果
- **PostgreSQL**: メインデータベース（ACID準拠・正規化設計・拡張性）
- **Redis**: キャッシュ・セッション管理

### 選定理由
- Django との親和性（Django ORM の標準サポート）
- 学習・実務双方での採用実績の高さ
- リレーショナルデータとしての World / Setting / 作品 の構造化に適する

## アーキテクチャ方針

### 技術スタック管理
- API設計・データベース設計・インフラ設定は本実装内で独自管理
- ビジネス要件・ドメイン概念・デザインコンセプトは `docs/` を参照

### 共通リソース活用
- **ビジネス要件**: `docs/business/` でビジネスルール・機能要件
- **ドメイン概念**: `docs/domain/` でエンティティ概念・関係性
- **デザインコンセプト**: `docs/design/` でUI/UXコンセプト
- **アセット**: `docs/assets/` で共通画像・ドキュメント
