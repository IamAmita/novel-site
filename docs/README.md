# プロジェクトドキュメント

小説投稿サイト（Python/Django実装）のドキュメント管理。

## ドキュメント構成

### project/ - プロジェクト概要
プロジェクトの基本情報・目的・方針を記述

- **概要.md**: プロジェクトの基本情報・目的・対象技術
- **技術選定方針.md**: 各技術の選定理由・学習目標・期待効果

### architecture/ - アーキテクチャ設計
システム全体の構成・設計方針を記述

- **システム構成.md**: 全体アーキテクチャ・インフラ構成・運用設計
- **データベース設計.md**: DB構成方針・データ管理戦略・同期仕様

### specifications/ - 仕様書
機能・API・データの仕様を記述

- **機能仕様.md**: 機能要件・API仕様・UI/UX仕様・非機能要件

### archive/ - アーカイブ
過去のドキュメント・詳細設計資料を保管

- **基本設計/**: 詳細なDB設計・API設計・画面設計
- **要件定義/**: 初期要件定義・機能要件定義
- **開発フロー.md**: 初期開発フロー

## ドキュメント方針

### 記述原則
- **簡潔性**: 要点を絞った説明記述
- **実用性**: 実際の開発・運用で参照する情報
- **更新性**: 変更に追従しやすい構成
- **検索性**: 必要な情報を素早く見つけられる構造

### 管理ルール
- **例示最小化**: コード例・詳細例は最小限に抑制
- **概念重視**: 技術の概念・方針・戦略を中心に記述
- **アーカイブ活用**: 詳細情報はarchiveで管理
- **定期更新**: プロジェクト進行に合わせて更新

## 参照順序

### 初回参照時
1. **project/概要.md**: プロジェクト全体の理解
2. **project/技術選定方針.md**: 技術選択の背景理解
3. **architecture/システム構成.md**: アーキテクチャ全体把握
4. **specifications/機能仕様.md**: 実装する機能の確認

### 開発時参照
- **architecture/**: 設計判断時の参照
- **specifications/**: 実装時の仕様確認
- **archive/**: 詳細情報が必要な場合の参照

---

**管理方針**: プロジェクト説明記述に特化  
**更新頻度**: プロジェクト進行に合わせて適宜更新
