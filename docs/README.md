# プロジェクトドキュメント

小説投稿サイト（Python/Django実装）のドキュメント管理。全ドキュメントは本 `docs/` 配下に一元化されている（2026-07-21、旧 `shared/` を統合）。

## ディレクトリ構成

```
docs/
├── project/          # プロジェクト方針・意思決定記録
├── business/         # ビジネス要件（技術非依存）
├── domain/           # ドメイン概念（技術非依存）
├── design/           # UI/UXコンセプト（技術非依存）
├── quality/          # 品質要件（技術非依存）
├── architecture/      # システム・DB設計
├── specifications/    # 機能仕様（索引）
├── assets/            # 共通アセット（画像等）
└── archive/           # 過去の要件定義・基本設計資料（参照用）
```

### project/ - プロジェクト方針
プロジェクトの基本情報・目的・意思決定の記録

- **概要.md**: プロジェクトの基本情報・目的・対象技術
- **プロダクト定義.md**: サイトの価値提案・提供機能
- **Phase1-確定メモ.md**: Phase 1 のスコープ・ドメイン構造の確定事項（**正本**）
- **技術選定方針.md**: 技術選定理由・学習目標・期待効果
- **要件インベントリ.md**: 関連ドキュメントの所在・矛盾点の整理記録
- 検討記録系ガイド（`*-ガイド.md`）: 各方針を確定させた際のQ&A記録（履歴）

### business/ - ビジネス要件（技術非依存）
全実装で共通の「何を作るか」を定義

- **functional-scope.md**: 機能範囲・Phase計画（**正本**）
- **user-stories.md**: ユーザーストーリー・受け入れ条件
- **business-rules.md**: ビジネスルール

### domain/ - ドメイン概念（技術非依存）
- **core-entities.md**: コアエンティティ定義（**正本**）
- **entity-relationships.md**: エンティティ関係図

### design/ - UI/UXコンセプト（技術非依存）
- **user-experience-flow.md**: UXフロー・原則

### quality/ - 品質要件（技術非依存）
- **performance-requirements.md**: パフォーマンス要件

### architecture/ - アーキテクチャ設計
システム全体の構成・設計方針

- **システム構成.md**: 全体アーキテクチャ・インフラ構成
- **データベース設計.md**: DB構成方針・データ管理戦略

### specifications/ - 仕様書（索引）
- **機能仕様.md**: 詳細ドキュメントへの索引

### assets/ - 共通アセット
- **images/**: 参考画像・図

### archive/ - アーカイブ
過去のドキュメント・詳細設計資料を保管（参照のみ、現行設計とは不整合な場合あり）

- **基本設計/**: 詳細なDB設計・API設計・画面設計（旧版）
- **要件定義/**: 初期要件定義・機能要件定義（旧版）
- **python-django-初期実装/**: 2026-05-25方針転換以前の python-django 要件定義書・設計書（Novel中心モデル、現行設計と不整合）
- **開発フロー.md**: 初期開発フロー

---

**技術依存の設計（API・DB・Docker等）は `implementations/python-django/` 側で独自管理する。**

## ドキュメント方針

### 記述原則
- **簡潔性**: 要点を絞った説明記述
- **実用性**: 実際の開発・運用で参照する情報
- **更新性**: 変更に追従しやすい構成
- **検索性**: 必要な情報を素早く見つけられる構造

### 管理ルール
- **例示最小化**: コード例・詳細例は最小限に抑制
- **概念重視**: 技術の概念・方針・戦略を中心に記述
- **アーカイブ活用**: 詳細情報はarchiveで管理
- **定期更新**: プロジェクト進行に合わせて更新

## 参照順序

### 初回参照時
1. **project/概要.md**: プロジェクト全体の理解
2. **project/Phase1-確定メモ.md**: 現在のスコープ・ドメイン構造の理解
3. **business/functional-scope.md**: 機能範囲の確認
4. **domain/core-entities.md**: エンティティ設計の確認
5. **architecture/システム構成.md**: アーキテクチャ全体把握

### 開発時参照
- **business/**・**domain/**: 要件・エンティティ設計の確認
- **architecture/**: 設計判断時の参照
- **specifications/**: 実装時の仕様確認（索引経由）
- **archive/**: 詳細情報・過去の経緯が必要な場合の参照

### 共通アセット利用
実装から相対パスで参照：
```
../../docs/assets/images/xxx.png
```
