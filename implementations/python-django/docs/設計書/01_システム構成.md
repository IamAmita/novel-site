## 1. アーキテクチャ概要

### 1.1 全体構成

本実装は **Django MTV パターン** のバックエンドと **React SPA** のフロントエンドを分離した構成を採用する。

```
ブラウザ
  │
  ├── http://localhost:3000  ─→  React SPA（Vite Dev Server）
  │                                  │ /api/* を Proxy
  └── http://localhost:8000  ─→  Django REST API
                                      │
                        ┌─────────────┼─────────────┐
                        ↓             ↓             ↓
                  PostgreSQL 15    Redis 7       （将来: S3）
                  （メインDB）    （キャッシュ）   （画像）
```

### 1.2 Django アプリケーション構成（MTV パターン）

```
backend/
├── manage.py
├── requirements.txt
├── novel_site/                   # プロジェクト設定
│   ├── settings.py
│   ├── urls.py                   # ルートURLconf
│   ├── wsgi.py
│   └── asgi.py
└── apps/                         # 機能別アプリケーション
    ├── users/                    # ユーザー系
    ├── novels/                   # 作品系
    ├── worlds/                   # 世界系（設定管理）
    ├── communications/           # コミュニケーション系
    ├── common/                   # 汎用系（カテゴリ・タグ）
    ├── masters/                  # マスタ系
    └── administration/           # 管理系
```

各アプリケーションの標準ファイル構成:
```
apps/{app_name}/
├── __init__.py
├── models.py         # Djangoモデル（DB テーブル定義）
├── serializers.py    # DRF シリアライザ（API 入出力定義）
├── views.py          # DRF ビュー（API ロジック）
├── urls.py           # アプリ内 URLconf
├── admin.py          # Django Admin 登録
├── permissions.py    # カスタム権限クラス
└── tests.py          # テストコード
```

## 2. Docker 構成

### 2.1 サービス一覧

| サービス名 | イメージ | ポート | 役割 |
|-----------|---------|--------|------|
| `db` | postgres:15-alpine | 5432 | PostgreSQL データベース |
| `redis` | redis:7-alpine | 6379 | キャッシュ・セッション管理 |
| `backend` | python:3.11-slim（自前ビルド） | 8000 | Django REST API |
| `frontend` | node:20-alpine（自前ビルド） | 3000 | React + Vite 開発サーバー |

### 2.2 サービス起動順序

```
db (healthcheck: pg_isready)
  └──┐
redis (healthcheck: redis-cli ping)
  └──┤
     └── backend (migrate → runserver)
           └── frontend (npm run dev)
```

### 2.3 ボリューム・マウント

| 対象 | ホスト側 | コンテナ側 | 目的 |
|------|---------|-----------|------|
| Django ソース | `./backend` | `/app` | ホットリロード |
| React ソース | `./frontend` | `/app` | ホットリロード |
| node_modules | （名前付き Volume） | `/app/node_modules` | OS 差異吸収 |
| DB データ | `postgres_data` (Volume) | `/var/lib/postgresql/data` | データ永続化 |

### 2.4 ネットワーク

Docker Compose のデフォルトネットワーク内で各サービスはサービス名（`db`、`redis`、`backend`）で名前解決する。

## 4. 認証・認可設計

### 4.1 JWT 認証フロー

```
クライアント                      Django Backend
    │                                  │
    │── POST /api/v1/auth/login ──────→│
    │   {email, password}              │ 認証情報を検証
    │←── {access, refresh} ───────────│
    │                                  │
    │── GET /api/v1/novels/ ──────────→│
    │   Authorization: Bearer {access} │ トークン検証
    │←── [novels...] ─────────────────│
    │                                  │
    │── POST /api/v1/auth/refresh ────→│
    │   {refresh}                      │ リフレッシュトークン検証
    │←── {access} ────────────────────│
```

### 4.2 トークン仕様

| 種別 | 有効期限 | 用途 |
|------|---------|------|
| アクセストークン | 30分 | API 認証 |
| リフレッシュトークン | 7日間 | アクセストークン再取得 |

### 4.3 権限レベル

| 権限 | 説明 | 取得方法 |
|------|------|---------|
| 読者（Reader） | 公開コンテンツの閲覧・コメント投稿 | 登録時にデフォルト付与 |
| 作者（Author） | 小説・設定の投稿・編集 | 申請制 |
| 管理者（Admin） | 全権限・管理機能 | 招待制 |

### 4.4 DRF 権限クラス設計

| クラス名 | 説明 |
|---------|------|
| `IsAuthenticated` | ログイン必須 |
| `IsOwnerOrReadOnly` | 所有者のみ編集・削除可能 |
| `IsAuthorOrReadOnly` | 作者権限を持つユーザーのみ投稿可能 |
| `IsAdminUser` | 管理者のみ |
| `AllowAny` | 認証不要（一覧・詳細などの公開エンドポイント） |

## 5. キャッシュ設計

### 5.1 キャッシュ対象と TTL

| 対象 | TTL | 説明 |
|------|-----|------|
| 小説一覧 | 5分 | 頻繁なアクセスが想定される一覧 |
| 小説詳細 | 10分 | 個別作品のキャッシュ |
| タグ一覧 | 60分 | 変更頻度の低いマスタデータ |
| カテゴリ一覧 | 60分 | 同上 |
| ユーザープロフィール | 10分 | 個別ユーザー情報 |
| 検索結果 | 3分 | 検索の重複クエリ削減 |

### 5.2 キャッシュ無効化タイミング

- 小説更新時 → 当該小説詳細・一覧キャッシュを削除
- コメント投稿時 → 当該小説のコメント一覧キャッシュを削除
- 管理者によるタグ・カテゴリ変更時 → 全関連キャッシュを削除

## 7. セキュリティ設計

### 7.1 Django セキュリティ設定

| 設定項目 | 値 | 説明 |
|---------|---|------|
| `DEBUG` | 本番: `False` | エラー情報を外部に露出しない |
| `SECURE_HSTS_SECONDS` | `31536000` | HSTS 有効化（本番） |
| `SECURE_SSL_REDIRECT` | `True`（本番） | HTTP → HTTPS リダイレクト |
| `SESSION_COOKIE_SECURE` | `True`（本番） | Cookie の HTTPS 限定 |
| `CSRF_COOKIE_SECURE` | `True`（本番） | CSRF Cookie の HTTPS 限定 |
| `X_FRAME_OPTIONS` | `DENY` | クリックジャッキング防止 |

### 7.2 入力バリデーション方針

- 全 API リクエストは DRF Serializer でバリデーション
- Django ORM を使用し、生 SQL は最小限に抑える
- アップロード画像はファイル種別・サイズを検証

### 7.3 ログイン保護

- ログイン失敗5回でアカウントロック（`login_histories` + `user_statuses` テーブルで管理）
- ロック解除は管理者操作または一定時間経過後

## 8. ログ設計

### 8.1 ログレベルと出力先

| レベル | 出力先 | 用途 |
|--------|--------|------|
| ERROR | コンソール + ファイル | 例外・DB エラー等 |
| WARNING | コンソール + ファイル | 認証失敗・権限エラー等 |
| INFO | コンソール | API アクセスログ |
| DEBUG | コンソール（DEBUG=True 時のみ） | 開発用詳細ログ |

### 8.2 操作履歴

重要な操作（作品の公開状態変更・削除・権限変更等）は `operation_histories` テーブルに記録する。
